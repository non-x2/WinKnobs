# v0.4.x Gaming プリセット機能 設計ドラフト（2026-07-05・WinKnobs 改良7-5）

> 🎯 v0.4.0〜v0.4.2 で Gaming カテゴリに5項目（GameMode/GameDVR/FullscreenOpt/TaskScheduling/HAGS）が揃った。
> 個別トグルは完成済みだが「複数設定の一括切替（プリセット）」は未設計のまま CHANGELOG Unreleased に残置されていた。
> 本ドラフトは**設計のみ**。実装はのんさん承認 → plan-validator 確認を経て別セッションで着手する。

## 0. スコープ

- 対象：既存 Gaming カテゴリ5項目（`gaming.gameMode` / `gaming.gameDvr` / `gaming.fullscreenOptimizations` / `gaming.taskSchedulingCategory` / `gaming.hags`）の一括適用。
- 非対象：新規レジストリ項目の追加。他カテゴリ（Graphics 等）への拡張は将来検討。カスタムプリセット編集 UI（案B）は今回見送り。

## 1. 案A：固定2プリセット（推奨）

- **「パフォーマンス重視」**：GameMode=ON／GameDVR=OFF（録画オーバーヘッド削減）／FullscreenOpt=OFF／TaskScheduling=High／HAGS=有効化。
- **「既定に戻す」**：5項目すべてを OS 既定値（未設定）へ一括 Restore。
- 実装コストが低い：各項目が既に持つ `Apply`/`Backup`/`Restore` を順次呼ぶだけで実現可能（新規レジストリロジック不要）。

## 2. 案B：カスタムプリセット（見送り）

- ユーザーが項目を自由選択して名前を付けて保存・複数管理。
- 保存形式・CRUD UI・命名衝突処理など実装コストが高い。**需要を見てから v1.0 系で再検討**（案Aで様子見）。

## 3. データ設計（案A採用時）

```csharp
private class GamingPreset
{
    public string Name { get; init; }
    public Dictionary<string, object> TargetValues { get; init; } // SettingItem.Id → 適用先の値/ラベル
}
```

- 適用時の一括バックアップ：対象5項目それぞれの `Backup()` を呼び、`Dictionary<string, string>`（Id→トークン）として1つの JSON にまとめて保持。「元に戻す」はこの一括トークンから各項目の `Restore()` を逆順で呼ぶ（個別の ↩戻すボタンと同じ土台を再利用・新規 Restore ロジック不要）。
- 途中失敗時の挙動は **未確定＝論点Q2**（下記）。

## 4. UI設計（叩き台）

- Gaming カテゴリは専用ペインを持たない（標準 DataGrid 表示・Graphics とは異なる）ため、DataGrid 上部に軽量なツールバー（ボタン2つ：「パフォーマンス重視を適用」「既定に戻す」）を追加する案。
- 適用前に確認ダイアログ（対象5項目・変更内容の一覧・🟡🔴混在の注意）を挟む＝個別トグルより影響範囲が広いため。

## 5. 確認したい論点（plan-validator 向け）

- **Q1（UAC 昇格の重複）**：HAGS・TaskScheduling は HKLM・要管理者。プリセット一括適用で UAC ダイアログが項目ごとに複数回出る可能性があり、UX として許容できるか（1回にまとめる方法があるか要調査）。
- **Q2（部分失敗時のロールバック方針）**：5項目中1つが Apply 失敗した場合、①適用済み分を自動ロールバック（全か無か）②失敗項目のみスキップして残りは適用のまま報告、のどちらにすべきか。
- **Q3（反映タイミングの違い）**：HAGS=要システム再起動／TaskScheduling=要管理者・次回ゲーム起動／他3項目=即時、と反映タイミングがバラバラ。「プリセット適用」ボタン1つでまとめることで「すぐ全部反映された」とユーザーが誤解しないか（確認ダイアログでの明記が必須）。
- **Q4（HAGS を「パフォーマンス重視」に含めるか）**：HAGS は VRAM+1GB のトレードオフがあり個別項目としては中立表記・非推奨寄り。プリセットで一括 ON にすると実質「推奨」を強めることにならないか（案：プリセットからは除外し4項目に絞る、も検討可）。
- **Q5（危険度表示）**：🟢🟡🔴 混在項目を1クリックでまとめて適用することへの注意喚起をどう出すか（確認ダイアログの文面設計）。
