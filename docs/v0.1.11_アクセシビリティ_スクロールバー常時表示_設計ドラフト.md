## 0. 目的・スコープ

Windows 11 の「スクロールバーを常に表示」（設定 > アクセシビリティ > 視覚効果 > スクロールバーを常に表示する）を
WinKnobs から1クリックで切替える。

- レジストリ：`HKCU\Control Panel\Accessibility\DynamicScrollbars`（REG_DWORD）。**0=常に表示 / 1(または未設定)=使う時だけ表示（既定）**。
- 管理者不要・危険度🟢・即戻せる。
- 反映：主経路は「新規に起動するアプリから反映」＋完全反映はサインアウト→再ログイン。**Win32 系（エクスプローラ等）には効かない既知制約**（設定/ストアアプリには効く）。live-apply（WM_SETTINGCHANGE ブロードキャストで設定/ストアアプリが再読込する可能性）は**未検証ゆえ今回は見送り**（v0.1.12 検証候補・もしかしたら思考）。
- ソース（前セッション WebSearch 確定）：thewindowsclub / windowscentral / MS Q&A。

## 1. 実装方針：Command 型 2択（宣言的 Boolean ではなく）

### なぜ宣言的 Boolean ではダメか（重要）
- `DynamicScrollbars` は**既定では存在しないことが多い**。
- 宣言的 Boolean（`ValueType.Boolean`）の退避は `BackupService.ExportKey`（.reg エクスポート）。
- .reg は「存在する値」しか記録できず、import 時に**ファイルに無い値を削除しない** → 「適用で新規作成 → 戻す」で**値が消えず残る＝戻せない**（TaskbarSi が JSON トークン退避を採用したのと同じ理由 / plan-validator V-4 既知パターン）。
- → **Command 型＋JSON トークン退避**（`ValueExisted` で「未設定なら削除して戻す」）にする。v0.1.9/v0.1.10 と同じ確実な復元。

### 設計
- Command 2択：`["使う時だけ表示（既定）", "常に表示する"]`（index0=既定/auto-hide=reg 1、index1=常に表示=reg 0）。
- Read：値 0 → "常に表示する"／それ以外・未設定 → "使う時だけ表示（既定）"。
- Apply：`"常に表示する"`→0 書込／それ以外→1 書込。
- Backup：`{ValueExisted = v != null, Value = 数値化(既定 1)}`。
- Restore：`ValueExisted ? 書込(Value) : DeleteValue`（未設定なら削除して元の"未設定"へ）。
- RestartScope=Logoff（ToHint「※ 一度ログオフして再ログオンで反映されます。」）。

## 3. API 設計（ScrollbarHelper）
```csharp
public static class ScrollbarHelper
{
    public const string RegistryPath = @"HKCU\Control Panel\Accessibility";
    public const string ValueName = "DynamicScrollbars";
    public const int ValueAlwaysShow = 0;
    public const int ValueAutoHide   = 1;
    public static IReadOnlyList<string> Choices { get; } // {"使う時だけ表示（既定）","常に表示する"}
    public static string AutoHideLabel   => Choices[0];
    public static string AlwaysShowLabel => Choices[1];
    public static bool   IsAlwaysShow(int? value);            // value==0
    public static int    ValueForLabel(string? label);        // AlwaysShow→0 / else→1
    public static string LabelForValue(int? value);           // 必ず Choices 内
}
```

## 4. 重要な設計判断（レビュー観点・先回り）
- **判断1（最重要）**：未設定問題のため Command＋JSON 退避（宣言的 Boolean は使わない）。§1 参照。
- **判断2**：退避の `existed = v != null`（REG_SZ 混在でもデータ消失しない・v0.1.10 の知見）。値は `v is int` でなければ既定 1 にフォールバック（DynamicScrollbars は通常 DWORD のみ）。
- **判断3**：Win32 アプリ（エクスプローラ等）に効かない既知制約を **Description に明記**（誤解防止）。完全反映は再ログイン。
- **判断4**：中立表示（既定＝「使う時だけ表示」を RecommendedValue に・一律「常に表示」を推さない）。
- **live-apply 見送り**：信頼できる API が無い（DynamicScrollbars は新規プロセスから反映）。P/Invoke 追加せず再ログイン案内（TextScaleFactor と同流儀）。
