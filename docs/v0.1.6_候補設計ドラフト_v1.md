## 🤖 AI 参照用詳細

### A. snapshot 改ざん対策（SHA256 / プレビュー / ACL）

**背景（裏付け）**：
- R-3 で `%APPDATA%\WinKnobs\backup\startup\` 配下に `.reg` snapshot を独自ローテーション 10 件で保存
- ファイルはユーザー権限で読み書き可 → 第三者プロセスが書換可能
- 復元時に改ざんされた .reg を `reg.exe import` すると **任意レジストリ書込が可能**（HKLM への昇格込み）
- 攻撃シナリオ：PUA／マルウェアが `[HKLM\Software\Microsoft\Windows\CurrentVersion\Run]` に永続化エントリを書込んだ snapshot を仕込む

**スコープ**：
1. snapshot 生成時：SHA256 ハッシュを別ファイル `snapshot_<timestamp>.sha256` として保存
2. 復元時：ハッシュ照合 → 一致しなければ確認ダイアログ（赤色警告）
3. （オプション）.reg ファイルを **`AdminAccess` を持つ ACL** に設定（書込禁止）

**実装概要**：
- `Services/BackupService.cs`：`BackupStartupSnapshot()` 内で SHA256 計算 + サイドカーファイル書出
- `Services/BackupService.cs`：`VerifyStartupSnapshotIntegrity(path)` 新規（戻り値：bool + 期待/実際ハッシュ）
- `ViewModels/Startup/StartupListViewModel.cs`：`RestoreSnapshot()` 内で `VerifyStartupSnapshotIntegrity` 呼出 + 不一致時 `_dialogs.Confirm` で続行確認
- ACL 設定（オプション）：`File.SetAccessControl()` で Owner=管理者 / User=Read only

**工数**：
- SHA256 ハッシュ生成・照合：1.5h
- 復元時 UI フロー：1h
- ACL 設定（オプション）：1.5h
- UIA テスト追加（tc_startup_restore_integrity）：1-2h
- 合計：4-6h

**依存**：なし（R-3 実装の上に乗る独立機能）

**フォールバック**：
- ACL は技術的に難しければ skip（SHA256 ハッシュだけで 80% 対応可能）

**検証**：
- Unit test：BackupService.VerifyStartupSnapshotIntegrity の 4 ケース（正常 / 改ざん / ハッシュファイルなし / SHA256 計算失敗）
- UIA test：tc_startup_restore_integrity（snapshot 生成 → 手動改ざん → 復元時警告表示確認）

### B. 世代またぎ復元の差分件数警告

**背景（裏付け）**：
- R-3 で snapshot 復元は「最新 snapshot」のみ復元
- 古い snapshot は `ListStartupSnapshots()` で取得可能だが UI 上は選択不可
- 「あ、もっと前の snapshot から戻したい」要望が出る可能性大
- 復元時、現在の Run キーと snapshot の差分件数（追加 N / 削除 N / 変更 N）が事前に分からない

**スコープ**：
1. RestoreSnapshot で復元前に差分を計算
2. 差分件数を `_dialogs.Confirm` で表示
3. 差分大（10 件以上）の場合は赤色強調

**実装概要**：
- `Services/BackupService.cs`：`AnalyzeSnapshotDiff(snapshotPath)` 新規
  - snapshot を temp 領域に reg.exe import 風にパース（ファイル読込のみ）
  - 現在のレジストリ（全 6 Run + 3 StartupApproved）を読込
  - 差分計算（追加 / 削除 / 変更）
- `ViewModels/Startup/StartupListViewModel.cs`：`RestoreSnapshot()` 冒頭で差分計算 + Confirm 文に組込
- 「変更」判定：Run キーの値（Command）比較

**工数**：
- 差分計算ロジック：0.5h
- Confirm 文組込：0.3h
- Unit test：0.5h
- 合計：1-2h

**依存**：A（SHA256）と分離可能・先に B のみ実装してリリースも可

**フォールバック**：
- 差分計算が複雑なら「件数のみ表示」（追加 N / 削除 N / 計 N 件変更）に簡略化

**検証**：
- Unit test：4 ケース（差分 0 / 1 / 5 / 10+）
- 手動：snapshot を意図的に変更（reg add）して復元 → 差分件数表示確認

### C. snapshot 復元前プレビュー UI

**背景（裏付け）**：
- B（差分件数警告）でも「具体的に何が変わるのか」がユーザーに見えない
- snapshot 復元は **元に戻せない**（さらに上書きが必要）破壊的操作
- UI 上で差分内容（before/after）を見せれば誤操作リスク激減

**スコープ**：
1. 新規ダイアログ `RestorePreviewDialog`
2. 3 ペイン：左=削除予定（赤）/ 中央=変更予定（黄）/ 右=追加予定（緑）
3. 確認チェックボックス：「内容を確認しました」→ 復元ボタン enable
4. キャンセル / 戻る対応

**実装概要**：
- `Views/Startup/RestorePreviewDialog.xaml(.cs)`（新規）
- `ViewModels/Startup/RestorePreviewViewModel.cs`（新規）
- `Services/BackupService.cs`：`AnalyzeSnapshotDiff` の戻り値を構造化（DiffResult: Added/Removed/Modified List）
- `ViewModels/Startup/StartupListViewModel.cs`：RestoreSnapshot で DialogService.OpenRestorePreview 呼出
- `Services/DialogService.cs`：OpenRestorePreview メソッド追加

**工数**：
- DiffResult 構造化：0.5h
- XAML/VM 実装：2h
- DialogService 統合：0.5h
- UIA テスト追加（tc_startup_restore_preview）：1-2h
- 合計：3-5h

**依存**：B（差分計算）が先行実装されている必要あり

**フォールバック**：
- ダイアログでなく既存 Confirm に差分テキストを長文で表示するだけでも 60% 達成
- ペイン分割せず単一 ListView で「[+追加] / [-削除] / [変更] 」プレフィックス表示でも妥当

**検証**：
- 手動：snapshot 復元前にダイアログ表示 → 差分内容確認 → キャンセル / 復元の両動線
- UIA test：tc_startup_restore_preview（ダイアログ起動・確認チェック・キャンセル）
