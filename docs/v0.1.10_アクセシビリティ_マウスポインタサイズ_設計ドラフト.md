## 0. 目的・スコープ

Windows の「マウスポインターのサイズ」（設定 > アクセシビリティ > マウスポインターとタッチ > サイズ）を
WinKnobs から1クリックで切替える。

- **管理者不要**（HKCU）・危険度🟢・即戻せる。
- 反映：`SystemParametersInfo(SPI_SETCURSORS)` で**即時反映を狙う**（best-effort）。失敗時も再ログインで確実反映。

### スコープ外（v0.2 候補）
- ポインタの色（白/黒/反転/カスタム）。
- 連続スライダー UI（本実装はプリセット選択式）。

## 1. レジストリ仕様（WebSearch で確定）

| 値 | パス | 型 | 範囲 | 役割 |
|---|---|---|---|---|
| `CursorSize` | `HKCU\Software\Microsoft\Accessibility` | DWORD | 1〜15 | 設定アプリのスライダー位置（1=標準） |
| `CursorBaseSize` | `HKCU\Control Panel\Cursors` | DWORD | 32〜256 | 実際の描画サイズ |

- **対応式**：`CursorBaseSize = 32 + (CursorSize - 1) × 16`（検算：1→32 / 2→48 / 8→144 / 15→256）。
- **2値とも書く**（設定アプリと同じ挙動＝スライダー表示と描画を一致させる）。
- **即時反映**：`SystemParametersInfo(SPI_SETCURSORS=0x0057, 0, NULL, SPIF_SENDCHANGE=0x02)` でカーソルをレジストリから再読込。
- ソース：elevenforum（CursorBaseSize 16刻み・SystemParametersInfo 再読込）/ MS Q&A。

## 2. 実装方針：TextScaleFactor と同型の Command 型（プリセット選択式）

- `BuildTextScaleItem()`（v0.1.9）と同型で `BuildPointerSizeItem()` を作る。
- 差分は **(a) 2値書込 (b) SPI による即時反映 (c) 2値ぶんの退避/復元**。
- プリセット（CursorSize 実値）：`1(標準)/2/3/4/5/8/11/15`。ラベルは**数字先頭**（`TryParseLabel` の先頭整数抽出が効くように）：`"1（標準）","2","3","4","5","8","11","15"`。

### P/Invoke（既存 `EnvironmentInfoService` と同作法）
新規 `Services/SystemCursorService.cs`：
```csharp
[DllImport("user32.dll", SetLastError = true, CharSet = CharSet.Auto)]
[return: MarshalAs(UnmanagedType.Bool)]
private static extern bool SystemParametersInfo(uint uiAction, uint uiParam, IntPtr pvParam, uint fWinIni);
// SPI_SETCURSORS=0x0057 / SPIF_SENDCHANGE=0x02
public static bool ReloadSystemCursors()  // try/catch・best-effort・失敗は false（再ログインで反映）
```
静的メソッド（状態なし・DI 不要）。MainViewModel から直接呼ぶ。

## 4. API 設計（CursorSizeHelper）

```csharp
public static class CursorSizeHelper
{
    public const string AccessibilityPath = @"HKCU\Software\Microsoft\Accessibility";
    public const string CursorSizeValue   = "CursorSize";
    public const string CursorsPath       = @"HKCU\Control Panel\Cursors";
    public const string CursorBaseSizeValue = "CursorBaseSize";
    public const int MinSize = 1, MaxSize = 15;
    public const int BaseSizeForMin = 32, BaseSizeStep = 16;

    public static IReadOnlyList<int>    PresetSizes { get; } // {1,2,3,4,5,8,11,15}
    public static IReadOnlyList<string> Choices     { get; } // {"1（標準）","2","3","4","5","8","11","15"}

    public static int    ClampSize(int size);          // [1,15]
    public static int    ToBaseSize(int cursorSize);   // 32+(clamp-1)*16
    public static bool   TryParseLabel(string? label, out int value); // 先頭整数抽出（"1（標準）"→1）
    public static string NearestPresetLabel(int cursorSize); // 必ず Choices 内（long距離・同距離は小さい方）
}
```

### MainViewModel.BuildPointerSizeItem()（Command）
- Read：`CursorSize`(int)あり→`NearestPresetLabel`／なし→`Choices[0]`。
- Apply：`TryParseLabel→ClampSize→size`、`ToBaseSize(size)→base`、**CursorSize と CursorBaseSize の2値を DWORD 書込**→`SystemCursorService.ReloadSystemCursors()`。
- Backup：2値の生値＋existed を `PointerSizeBackup` に保存。
- Restore：各値 existed?書込:削除 → `ReloadSystemCursors()`。
- `Id="accessibility.pointerSize"`、Risk=Green、RestartScope=None（SPI 即時・fallback 再ログインは Description）。中立：RecommendedValue=`Choices[0]`（標準）。

## 5. 重要な設計判断（レビュー観点・先回り）

### 判断1：2値とも書く（CursorSize だけ／CursorBaseSize だけ にしない）
- CursorBaseSize＝実描画・CursorSize＝設定アプリのスライダー表示。**片方だけだと設定アプリの表示と実サイズが食い違う**。両方を対応式で同期。
- 退避も2値独立（first-touch ではなく単純な適用前スナップショット・初回 Backup のみ＝SettingDialogViewModel の Command 仕様どおり）。

### 判断2：SPI は best-effort・RestartScope=None
- `SystemParametersInfo(SPI_SETCURSORS)` でカーソル再読込＝即時反映を狙う。**TextScaleFactor の broadcast 見送りとは逆**＝こちらは SPI が実際にサイズ反映する“生きたコード”（死にコードではない）。
- 失敗（try/catch で false）でも**再ログインで確実反映**。Description に明記。

### 判断3：ラベルは数字先頭
- `TryParseLabel` は TextScaleHelper と同じ「先頭整数抽出」。「標準（1）」だと先頭が非数字で parse 失敗 → **「1（標準）」と数字先頭に**。`NearestPresetLabel` は Choices 配列から直接引く（必ず Choices 内＝ComboBox 整合・v0.1.9 plan-validator 致命の再発防止）。

### 判断4：Read は CursorSize 基準
- Read は `CursorSize`(Accessibility) のみ読む（設定アプリのスライダー値）。CursorBaseSize は描画用で Read には使わない。CursorSize 欠落時は「標準」表示（実害なし）。
