## 0. 一言

新「🔊 サウンド」カテゴリの第1項目として、Windows のシステム効果音を **ON（標準）/ OFF（消音）** で切り替える Command 型2択。
HKCU・管理者不要・完全可逆。直近の SearchBoxMode（Command＋退避）と GraphicsService（first-touch-wins 退避）の確立パターンを踏襲。

---

## 1. なぜ「(Default) だけ書く」では不十分か（最重要・実装の肝）

候補リストの「`HKCU\AppEvents\Schemes` の `(Default)` を `.None` に」だけでは**実際には消音されない**。

- 効果音は再生時、各イベントの `HKCU\AppEvents\Schemes\Apps\<App>\<Event>\.Current\(Default)`（.wav パス）を直接読む。
- トップの `Schemes\(Default)` は「サウンド設定 UI で選択中のスキーム名」にすぎず、**再生時には参照されない**。
- サウンド コントロールパネルで「サウンドなし」を Apply すると、CPL が各 `.Current` を空に書き換える。レジストリ直編集で `(Default)` だけ変えると**鳴り続ける＝偽トグル**。

→ 正しい実装は **各イベントの `.Current\(Default)` を空文字に書き換える**こと（OFF）。ON は各 `.Current` を `.Default`（標準スキームの値）から復元。

### 1-1. REG_EXPAND_SZ 問題（無音バグの罠）

`.Current\(Default)` の値は `%SystemRoot%\media\Windows Foreground.wav` のような **REG_EXPAND_SZ**（環境変数展開型）が混在する。
退避時に**値だけ**保存して REG_SZ で復元すると、`%SystemRoot%` がリテラル文字列になり .wav が見つからず**無音化＝復元失敗**。
→ 退避は **値 + 型(RegistryValueKind)** をペアで保存し、復元時に同じ型で書き戻す。

## 2. レジストリ仕様

| 用途 | パス | 値 |
|---|---|---|
| スキームポインタ（UI 表示用） | `HKCU\AppEvents\Schemes` `(Default)` | `.Default`=標準 / `.None`=なし |
| 各イベントの実効サウンド | `HKCU\AppEvents\Schemes\Apps\<App>\<Event>\.Current` `(Default)` | .wav パス（REG_SZ / REG_EXPAND_SZ）or 空="" |
| 標準スキームの参照元 | `HKCU\AppEvents\Schemes\Apps\<App>\<Event>\.Default` `(Default)` | 標準サウンドの .wav（ON 復元の出所） |

列挙：`Apps` 直下の各 App キー → 各 Event キー → `\.Current` を持つものが対象。

## 3. 操作セマンティクス

| 操作 | 内容 |
|---|---|
| **Read** | トップ `Schemes\(Default)` == `.None` → 「効果音オフ（消音）」／それ以外 → 「効果音オン（標準）」 |
| **Apply(OFF=消音)** | first-touch 退避 → 全 `.Current\(Default)` を `""`(REG_SZ) に → トップ `(Default)`=`.None` |
| **Apply(ON=標準)** | first-touch 退避 → 各 `.Current\(Default)` を兄弟 `.Default\(Default)`（値+型）からコピー → トップ `(Default)`=`.Default`。`.Default` 無しイベントは触らない |
| **Backup()**（framework 初回 Apply 前に1回） | `SystemSoundService.BackupFirstTouch()` を呼び、非null マーカー `"systemsounds"` を返す（CanRestore 有効化用） |
| **Restore(token)**（個別「戻す」） | `SystemSoundService.RestoreAll()`＝退避から各 `.Current`（値+型）＋トップスキームを厳密復元 → 退避クリア |

**退避方針**＝GraphicsService と同型：`BackupService` の maintenance ストア（FeatureKey=`"systemsounds"`）に first-touch-wins で1度だけ JSON 退避。Apply を何度繰り返しても原状は上書きしない。RestoreAll 成功後に退避削除＝次の first-touch を許す。

退避 JSON 構造：
```json
{
  "scheme": ".Default",
  "events": {
    "Apps\\.Default\\SystemAsterisk\\.Current": { "v": "%SystemRoot%\\media\\Windows Foreground.wav", "k": 2 },
    "...": { "v": "", "k": 1 }
  }
}
```
（k = RegistryValueKind の int 値：1=String, 2=ExpandString）

## 5. エッジケース3周

**機能**
1. `.Current` を持たないイベント／App キー → スキップ（対象外）。
2. `.Default` が無いイベントで Apply(ON) → そのイベントは触らない（無理に "" にしない）。
3. 既にユーザーが `.None` 運用中で WinKnobs 初操作が ON → 退避は「現状（=消音）」を捕捉。ON で .Default から標準音復元。「戻す」で消音へ厳密復帰。
4. REG_EXPAND_SZ の値 → 型ごと退避・復元（§1-1）。

**環境**
5. `Apps` キー自体が存在しない異常環境 → 列挙0件・例外にせず no-op（IsMuted は ON 既定表示）。
6. 一部イベントキーが他プロセスでロック／書込失敗 → DeleteValue/WriteValue 失敗を握り潰さず**集計して最後に throw**（GraphicsService RestoreAll と同型・サイレント失敗禁止＝見落とし事例 2026-06-10）。
7. 退避 JSON 破損（JsonException）→ これ以上壊さず後始末のみ（GraphicsService 同型）。

**時間／並行**
8. first-touch-wins は単一インスタンス前提（v0.3.1 SingleInstanceManager で同一セッション単一化済）。残既知制約＝クロスセッションのみ（既存 Network/Graphics と同じ）。
9. framework の Backup は初回 Apply のみ（SettingDialogViewModel S-1 修正）＝ダイアログ内 first-touch 安全。サービス側 maintenance ストアの first-touch-wins と二重で原状を保護。

## 6. 反映タイミング

各 `.Current` を直接書くため、**以後再生される効果音は即時に反映**（再ログイン不要）。
ただし常駐アプリが起動時にサウンドをキャッシュする場合があり、完全反映に一部アプリの再起動が要ることがある旨を説明文に明記。RestartScope=None。

## 7. UI 文言（説明文ドラフト）

> Windows の効果音（通知音・警告音・起動関連の効果音など）をまとめてオン/オフします（設定 > システム > サウンド、または「サウンド」コントロールパネルの「サウンドなし」スキームと同じ効果）。
> 「効果音オフ（消音）」は各イベントのサウンドを空にして無音化します。「効果音オン（標準）」は Windows 標準のサウンドに戻します。
> 個別の「↩ 戻す」で、WinKnobs が変更する前のサウンド設定（あなたのカスタム設定を含む）に正確に復元できます。
> 管理者権限は不要です（自分のユーザー設定）。⚠️ 一部の常駐アプリは再起動するまで古い音が鳴ることがあります。

危険度＝🟢Green（見た目/音の変更・即戻せる）。中立表示（ON/OFF どちらも推奨しない）。

## 9. @plan-validator 反映（2026-06-29・条件付きNO-GO→反映でGO）

**指摘1（Read の偽陽性/偽陰性）→ ポリシー確定**：状態表示は **トップスキームポインタ基準の速読**（`Schemes\(Default)==.None`→OFF／他→ON）を採用。外部ツールで `.Current` だけ半端に変更された環境では実状態とズレ得るため、§7 UI 文言に「この表示は選択中のサウンドスキーム基準で、外部ツールで個別変更した場合は実際の鳴り方と一致しないことがあります」を追記。サンプリング確認は I/O コスト・偽陰性増のため不採用（Apply は決定的なので表示ズレは実害小）。

**指摘2（GetSubKeyNames 仕様）→ 明記**：
```csharp
/// <summary>指定キー直下のサブキー名を列挙（v0.3.3 効果音：Apps/各App/各Event の3段列挙用）。
/// キー無しは空配列。GetValueNames（値名列挙）と対称の薄いラッパー。</summary>
public string[] GetSubKeyNames(string keyPath)
{
    var (hive, subKey) = ParsePath(keyPath);
    using var key = hive.OpenSubKey(subKey, false);
    return key?.GetSubKeyNames() ?? Array.Empty<string>();
}
```
パス構築（Apps\<App>\<Event>\.Current）は純粋関数 `SystemSoundHelper.BuildEventCurrentPath(app, ev)` に切出し xUnit 化。列挙2段（Apps→App→Event）は Service の I/O 側。

**指摘3＋Choices 定義 → 確定**：`SystemSoundHelper.Choices = ["効果音オン（標準）","効果音オフ（消音）"]`（index0=ON, index1=OFF）。`LabelForScheme(scheme)`＝`.None`→Choices[1] else Choices[0]（必ず同一参照）。`IsMuteLabel(label)`＝ReferenceEquals/== Choices[1]。§7 文言に「『オン（標準）』を適用するとカスタム音は Windows 標準音に置き換わります。カスタム音へ戻すには『↩ 戻す』を使ってください」を追記。

**エッジ1（null vs "" 区別）→ 退避構造変更**：退避エントリに `existed` を追加。
```json
"events": { "Apps\\.Default\\SystemAsterisk\\.Current": { "existed": true, "v": "...", "k": 2 } }
```
`(Default)` 値が無い（ReadValue が null）イベントは `existed=false` で退避。Restore は `existed=false`→DeleteValue（WinKnobs が書いた "" を取り消し原状＝値なしへ）。`existed=true`→値+型で書戻し。これで「空文字の無音」と「値なし未設定」を厳密に区別。

**エッジ4＋Restore 削除タイミング → GraphicsService 同型に確定**：RestoreAll は (a)退避デシリアライズ→(b)各イベント書戻し/削除（失敗は集計）→(c)`RemoveMaintenanceOriginal`（退避削除）→(d)`deleteFailed/writeFailed>0` なら最後に集計 throw（失敗パス先頭3件をメッセージに含める）。**部分失敗でも退避は消える**（GraphicsService 203 行と同ポリシー＝再試行より「壊し過ぎない」優先）。この挙動をコメントに明記。

**エッジ3（WU/AudioSrv 競合・ゴースト鍵）→ スキップ方針**：Restore 書戻し時、対象の `.Current` キーが現存しなければ**スキップ**（WriteValue の CreateSubKey で孤児キーを復活させない）＝退避に在るが実体消失したイベントは触らない。集計 throw 対象外。

**依存反映**：
- `CategoryType.Sound` は enum 末尾追加＋Graphics 同様のドキュメントコメント（「専用ペイン不要・標準 DataGrid 表示・IsStandardCategorySelected は変更不要」）。
- `IsStandardCategorySelected`（MainViewModel 224 付近 `!(isStartup||isNetwork||isGraphics)`）は **変更不要**（Sound は専用ペイン無し＝Maintenance と同じ標準 DataGrid 経路で true）。
- カテゴリ表示順：`InitializeCategories` で **グラフィックの直後**に `🔊 サウンド` を Add。
- `SystemSoundService` は **AddSingleton**（理由：Transient だと BackupService の first-touch-wins 判定が毎回リセットされ二重退避を招く＝コメント明記）。
- maintenance `originals.json` は Graphics と共有だが FeatureKey=`systemsounds` で分離。同一プロセス内 UI スレッド直列なので現状競合なし（将来 async 化時の注意をコメント）。
- §7 文言に「Windows の『サウンド』設定／コントロールパネルを開いている場合は閉じてから適用」（キーロックで集計 throw 発動回避）を追記。

**xUnit 追加**：純粋関数（ラベル↔スキーム同一参照・退避 JSON 往復・existed/型 int↔Kind・BuildEventCurrentPath）＋**多数イベント（~1000件）退避往復**の健全性。
