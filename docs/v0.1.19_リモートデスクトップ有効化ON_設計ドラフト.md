> 1. 🔴【最致命・§2 を上書き】**単発 powershell の「スクリプト内 try/catch ロールバック」方式は撤回**。原子性を担保できない（catch自体の失敗が二次catch無し／`-Command` 内 throw の ExitCode が0素通りし得る／FW開放後にロールバック権限喪失で攻撃口が開いたまま中途半端 ExitCode）。
>    → **C# 側 done-stack 方式に変更**（`NetworkService.ApplyDoh` 427-465行・特に453行の「ロールバックを内側catchで握って必ずthrow」を手本）。3ステップ（NLA=1 / fDeny=0 / FW Enable）を**個別**に実行し C# で `done` に積む→失敗したら逆順で巻き戻し→巻き戻し自体の失敗は内側 try/catch で握る→上位へ通知。
>    - **結果は4分岐に拡張**：`Success / AccessDenied / Failed / LeftExposed`。`LeftExposed`＝「FW を開けた後に後続失敗＋ロールバックでも閉じ直せなかった＝攻撃口が開いたまま」。この時だけ **🔴強警告**（「外部接続を受け付ける状態のまま失敗しました。今すぐ『無効にする』を管理者で実行するか、Windows設定で確認してください」）。enum に `LeftExposed` 追加、`MainViewModel` の switch も4分岐へ。
>    - 各ステップの権限不足は `ElevationClassifier.LooksLikeAccessDenied` で分類（既存流用）。
>    - FW は「開ける」だけ Step3 で最後、ロールバックでは「Step3 で開けた規則のみ閉じる」。**退避 record の `FwTcpWasEnabled/FwUdpWasEnabled` が true（元々開いていた）なら、その規則はロールバック対象外**（元ON分を誤って閉じない）。
>    - FW 規則 TCP/UDP の**片方が存在しない**環境：**TCP 必須・UDP は best-effort**（UDP 欠如/失敗は警告に留め ON 成立とする。UDP は体感品質用で必須ではない）。BuildDisableCommand（両方一括）とは非対称にする。
> 2. 🔴【依存・問4 を上書き】**孤児退避の UX 事故を断つ**。`NetworkService.RevertAll`（337行）は固定3キー配列で回すため、network/originals.json に "remoteDesktop" を同居させても「ぜんぶ戻す」では戻らず、ユーザーが戻したつもりになる事故が確実。
>    → 対策（両方やる）：(a) **退避保存先を Maintenance 専用 `backup\maintenance\originals.json` に分離**（network ストアに同居させない＝NetworkService.RevertAll の対象外であることを構造で明示・DoH退避の道連れ破損も回避）。`BackupService` に `SaveMaintenanceOriginalIfAbsent/LoadMaintenanceOriginals/RemoveMaintenanceOriginal` を追加（network 版のコピー＝薄い）。(b) 専用「リモートデスクトップを元に戻す」メニューで first-touch 復帰。(c) Red ダイアログ／README に「**ON は『ぜんぶ戻す』では戻りません。『無効にする』か『元に戻す』を使ってください**」と明示。**※問4 の推奨を A（network同居）から「専用ストア分離」へ変更**（道連れ破損＋逆依存＋孤児を一掃）。
> 3. 🔴【スレッド・§5(3) を上書き】**ShowDialog は UI スレッド・Enable のみ Task.Run**。順序を固定：①UIスレッドで `ReadStatus`→②UIスレッドで Red ダイアログ `ShowDialog`（`Task.Run` の中で UI 生成は即例外）→③同意時のみ `await Task.Run(() => _remoteDesktop.Enable(out err))`→④await 後 UIスレッドで結果表示。`IsRemoteDesktopBusy` は**ダイアログ表示中から**立てる（表示中の再 Invoke も封じる）。Red ダイアログは `DialogService` 経由で表示し Owner 指定／重複ガードの恩恵を受ける（`RestorePreviewDialog` の DialogService 経由表示＝189-200行に倣う・ViewModel から直接 new しない）。
> 4. 🟡【§3/§5(2)】**ReadStatus は各項目を独立 try で囲み、読めない項目は「不明」で返す**。特に `RDP-Tcp\UserAuthentication`(NLA) は ACL が厳しく**非昇格で読めない環境がある**（TrustedInstaller/SYSTEM 寄り ACL）。NLA 読取失敗＝「NLA 不明」で返し ReadStatus 全体を落とさない（ダイアログのコンテキスト提示を全滅させない）。VM 検証に「非昇格 ReadStatus で NLA が『不明』で返る」を追加。

## 0. ⚠️ 実装前のダメ出し（やめた方がいいこと・「載せない」選択肢も明示）

1. 🔴 **そもそも ON を載せるべきか、もう一度問う**。のんさんは目の前のPCを操作する単独ローカル利用で、RDP ON の実利はほぼ0・攻撃面だけ増える。**「載せない（v0.1.18 の OFF 専用つまみで完結）」も依然として有力な選択肢**。OSS の網羅性（いじくるツール代替）を取るか、安全最大を取るかの価値判断。→ §1 で判断リクエスト。
2. 🔴 **OFF（Disable・単発 powershell＋fail-closed）の成功体験を機械コピーしない**。ON は「全成功 or 全巻き戻し」が要る（中途半端な開放を残さない）。Disable の `;` 連結・ErrorAction Stop・ロールバック無しモデルをそのまま流用すると、NLA だけ書けて FW 開かず等の片肺状態を生む。
3. 🔴 **退避（backup）無しの ON は事故**。ON は「元の NLA は 0 だった／FW は無効だった」を `*Existed` で正確に戻せないと、ユーザーの元の姿勢を破壊する（NLA を勝手に 1 のまま固定する等）。
4. 🔴 **素の MessageBox（ConfirmDestructive）で ON を出さない**。チェック同意・コンテキスト提示ができない。Red 専用ダイアログ新規実装が必須。
5. 🟡 **「おすすめ一括適用」「推奨値」に ON を絶対含めない**（意図せず ON の大事故）。推奨＝「無効（既定）」固定を堅持。
6. 🟡 **WAN 露出は WinKnobs では制御不能**（ルータの UPnP/ポート開放次第で 3389 が WAN に出る）。「同一LAN内のみ推奨」と書いても過信させない文言を必須に。
7. 🟡 **状態が見えないまま ON を出さない**。OFF は「閉じるだけ」で状態表示なしでも安全だったが、ON は「今 ON/OFF どっち？NLA は？ポートは？自分はリモート接続中か？」が見えないと判断を誤る。**ReadStatus（状態読み取り）は v0.1.19 で必須化**（v0.1.18.1 送りにしていた状態表示を ON とセットで前倒し）。

## 2. 対象設定・適用順・トランザクション（ON 固有）

### 3要素（v0.1.18 §2 と同じ・ON は NLA も書く）
| 要素 | 場所 | ON 時の値 | 手段 |
|---|---|---|---|
| **NLA (UserAuthentication)** | `HKLM\...\Terminal Server\WinStations\RDP-Tcp` (REG_DWORD) | **1=必須（安全側・強制）** | PowerShell `Set-ItemProperty` |
| **fDenyTSConnections** | `HKLM\System\CurrentControlSet\Control\Terminal Server` (REG_DWORD) | 0=許可 | PowerShell `Set-ItemProperty` |
| **FW 規則** | `RemoteDesktop-UserMode-In-TCP` / `-In-UDP`（安定Name） | Enabled=True | PowerShell `Enable-NetFirewallRule -Name <安定ID>` |

> FW は v0.1.18 で確立した通り **PowerShell `*-NetFirewallRule -Name`**（netsh はローカライズ表示名問題で不可）。読み取りは `Get-NetFirewallRule -Name … | Select Enabled`。

### 適用順＝**内→外**（攻撃口を最後に開ける・締め出し回避の鉄則）
1. **NLA を 1**（安全側を先に固める＝認証必須にしてから開ける）
2. **fDeny を 0**（OS 上で接続許可）
3. **FW 規則を Enable**（最後に外部口を開ける）

### トランザクション＝**全成功 or 全巻き戻し**（OFF の fail-closed とは逆）
- ON は「中途半端な開放を残さない」ため、適用中どこかで失敗したら **この適用で書いた分を逆順で元へ戻す**（FW閉→fDeny戻す→NLA戻す）。`NetworkService.ApplyDoh`（427行・done 蓄積→逆順巻き戻し→例外送出）が手本。
- **実装方式の決定（重要）**：単発 `powershell.exe -Command` の**スクリプト内 try/catch で完結**させる。冒頭で現状3値をスナップショット→try で内→外に適用→catch で逆順ロールバック→`throw`（ExitCode!=0）。
  - 理由：v0.1.18 Disable と同じ「1プロセス・ExitCode で Classify」モデルを維持（C# 多段の新機構を足さない）。ロールバックは PS スクリプト内に閉じる＝原子性をOSコマンド層で完結。
  - これは「この適用の原子性」。後述の **JSON 退避（§3）は別物**（後でユーザーが first-touch 状態へ戻すための永続退避）。

> ⚠️ 自己セッション判定（§4）が「リモート接続中」を返す場合、ON 適用そのものは締め出しを起こさない（開ける方向）が、**ON 時は別の罠**＝NLA=1 強制で「古いクライアントから今後繋がらなくなる」可能性。ダイアログで明示（§4）。

## 3. 退避（first-touch backup）— ユーザーの元の姿勢を壊さない

- ON 適用の**前**に現状3値を読み、`RemoteDesktopBackup` record にまとめて `SaveNetworkOriginalIfAbsent("remoteDesktop", json)` で **first-touch-wins** 保存（既に退避があれば上書きしない＝一番最初の素の状態を保持）。
- record：`record RemoteDesktopBackup(bool FDenyExisted, int FDenyValue, bool FwTcpWasEnabled, bool FwUdpWasEnabled, bool NlaExisted, int NlaValue)`
- `*Existed=false`（元々キーが無かった）なら復元時は**削除して既定へ**（無かったものを 0 で作らない）。fDeny は「キー無し＝RDP 無効（既定）」が安全側で正しい。
- 復元 `RestoreRemoteDesktop(json)`：安全順 **FW→NLA→fDeny**。途中失敗時は §3.1。

### 3.1 復元の部分失敗保証（中間状態を安全側に倒す）
- 復元途中で AccessDenied 等で止まったら、**退避は残す**（管理者で再試行可）＋最後に「ともかく fDeny=1・FW 閉（防御既定）へ寄せられる範囲で寄せる」フォールバック。UI に「完全復元に失敗。安全のため『無効』寄りに留めました。管理者で再実行を」と明示。露出側中間状態（OS 許可なのに FW だけ閉、等の逆＝OS 許可＋FW 開きっぱ）を放置しない。

### 3.2 退避破損時の復旧
- 退避 JSON が壊れて読めない場合の既定復旧＝「ともかく fDeny=1・FW 閉で安全側」。UI に「退避情報が読めず、安全のため『無効』にしました」と明示。

## 4. Red 専用 強確認ダイアログ（新規実装・本機能の心臓）

`DialogService.ConfirmDestructive`（58行・素の MessageBox・チェック不可）では足りない。**新規 `RemoteDesktopEnableDialog`（Window）＋`RemoteDesktopEnableViewModel`** を作る。参考実装＝`RestorePreviewDialog`/`RestorePreviewViewModel`（startup 専用・流用不可だが構造の手本）。

### 必須要素
1. **危険度🔴バッジ＋赤系配色**（一目で「重い操作」と分かる）。
2. **何が起きるか（平易な日本語）**：「外部からこのPCに接続できる入口（攻撃口）が1つ増えます」。
3. **現在のコンテキスト提示**（ReadStatus から）：
   - 対象ユーザー名（`Environment.UserName`）
   - 現在の LAN IP（複数なら列挙）
   - RDP ポート（`RDP-Tcp\PortNumber`・既定3389／変更時は強調）
   - **あなたは今リモート接続中か**（`IsCurrentSessionRemote`）
   - 現在 ON/OFF・NLA 現状
4. **推奨対策の同時提示**：NLA が自動で必須(1)になること／強いパスワード推奨／**同一LAN内のみ推奨・公共Wi-Fi/共有PCでは有効化しない**／WAN 露出はルータ次第で WinKnobs では保証外。
5. **既定フォーカス＝[キャンセル]**（誤確定防止）。
6. **明示同意ジェスチャ**＝チェックボックス「リスクを理解しました」ON で初めて [有効化] ボタンが活性（問2-A）。
7. **戻し方の保証**：「適用前に現在の設定を退避します。WinKnobs の『無効にする』または『元に戻す』でいつでも戻せます」。

## 6. テスト計画

### xUnit 純粋関数（`RemoteDesktopHelperTests.cs` 追記）
- `BuildEnableCommand()`：生成文字列に「内→外順」「スナップショット取得」「catch ロールバック」「ErrorAction Stop」が含まれることを構造検証（部分文字列 Assert）。
- `ParseFirewallEnabled`：`Get-NetFirewallRule` 出力サンプル（英/日・Enabled True/False・読めない→false）。
- `IsRdpEnabled`：(0,true)→true /(1,true)→false /(0,false)→false。
- `DescribeRdpState`：有効/無効/一部だけ有効/NLA不明 ＋ but-caveat 文の有無。
- `Classify`（既存）：ON でも同じ ExitCode 経路を確認。

### VM 実機検証（**接続往復が必須**＝ON の核心・新規スクリプト `_vm_remotedesktop_enable_verify.ps1`）
- チェックポイント `Before_v0.1.19_RemoteDesktop_Enable`。
- **接続往復**：VM内で Enable → ホスト→VM へ `Test-NetConnection -ComputerName <VM IP> -Port 3389`（または mstsc 試行）で **到達 OK** → Disable → **到達不可** → 原状復帰。状態レジストリ確認だけでは「実際に繋がるか」を保証できないため必須。
- NLA=1 が書かれること・fDeny=0・FW 規則 Enabled を実測。
- **部分失敗ロールバック検証**：FW Enable を意図的に失敗させ（規則名を一時改変等）、NLA/fDeny が**元へ巻き戻る**ことを確認。
- **退避**：originals.json に `remoteDesktop` first-touch が記録されること／`RestoreRemoteDesktop` で元へ戻ること／退避破損時に安全側へ倒れること。
- 非昇格 Enable → AccessDenied 経路。

### UIA 非破壊（`tc_maintenance_remotedesktop_enable.ps1` 新規・`tc_maintenance_protection` 同型）
- メニュー `MenuEnableRemoteDesktop` 存在→Invoke→**Red ダイアログ出現**→チェックボックス未チェック時 [有効化] が**非活性**であることを確認→既定フォーカス＝[キャンセル]→キャンセルで閉じる→結果ダイアログ無し→fDeny レジストリ不変。**チェックを入れて[有効化]は押さない**（実 ON を走らせない）。
- ⚠️ ConfirmDestructive ではなくカスタム Window なので、UIA 検出ロジックは新規（ボタン/チェックボックスを AutomationId で引く）。Red ダイアログのコントロールに AutomationId を必ず付ける（`CheckUnderstandRisk` / `BtnEnable` / `BtnCancel`）。
