## 1. 機能A：グラフィック設定（🎨 新カテゴリ＋専用ペイン）

### 1-1. レジストリ仕様（WebSearch 2026-06-21 で確定）

- キー：`HKCU\Software\Microsoft\DirectX\UserGpuPreferences`（**HKCU＝管理者不要**）
- **アプリ別設定**：値名＝exe のフルパス（例 `C:\…\chrome.exe`）、データ＝REG_SZ `GpuPreference=N;AutoHDREnable=M;`
  - `GpuPreference` … `0`=Windowsに任せる／`1`=省電力GPU(iGPU=UHD630)／`2`=高パフォーマンスGPU(dGPU=GTX1080)
  - `AutoHDREnable` … `0`/`1`（任意トークン）
  - その他 `SpecificAdapter=…` 等の未知トークンが付くことがある → **保持必須**
- **全体（既定の設定）**：値名 `DirectXUserGlobalSettings`、データ＝REG_SZ `SwapEffectUpgradeEnable=1;AutoHDREnable=…;…`
  - `SwapEffectUpgradeEnable` … ウィンドウゲームの最適化（全体）
  - `AutoHDREnable` … Auto HDR（全体）
- 反映：**対象アプリの再起動で反映**（Windows公式 UI も「ゲームを再起動」と明記）。全体トグルは即〜再ログオン。
- リスク：🟢（HKCU・即戻せる・リセット＝値削除）

> 💡 のんさんPC（GTX1080+UHD630）は Claude/Chrome を既に手動で高パフォーマンス(GTX1080)に設定済（スクショ確認）。アプリ別GPU切替は日常的に使う実用機能。memory `reference_chromium_igpu_preference_restart` 参照。

- 各アプリ行＝`GpuAppEntry : ObservableObject`（FullPath / DisplayName=basename / GpuPreference(0/1/2) / AutoHdr bool / OtherTokens 保持）
- GPU ドロップダウン変更 or Auto HDR トグル → 即 Apply（その行の値を書込）。Network の「変更したら即適用」と異なり**行単位**なので、変更時に1行だけ書く。
- 🗑リセット＝その値を削除（Windows公式の「リセット」と同義）。
- ➕追加＝OpenFileDialog で exe 選択 → `GpuPreference=0;` で新規行追加（まだ書込まず、ユーザーがGPUを選んだ時点で書込）。重複パスは既存行へフォーカス。

**`Services/GpuPreferenceHelper.cs`（純粋関数・xUnit）**

## 2. 機能B：仮想メモリ（💾 ページファイル・🔴 Red・ツールメニュー＋専用ダイアログ）

### 2-1. 仕様・リスク（WebSearch 2026-06-21 で確定）

- 現状読取：
  - `Get-CimInstance Win32_ComputerSystem` → `AutomaticManagedPagefile`（bool＝「すべてのドライブを自動管理」）
  - `Get-CimInstance Win32_PageFileSetting` → `Name`（例 `C:\pagefile.sys`）・`InitialSize`・`MaximumSize`（MB・0 0＝システム管理）
- 書込：
  - 自動管理ON … Win32_ComputerSystem.AutomaticManagedPagefile = $true
  - 手動 … AutomaticManagedPagefile = $false → Win32_PageFileSetting（C:）に InitialSize/MaximumSize 設定。あるいはレジストリ `HKLM\…\Memory Management\PagingFiles`（REG_MULTI_SZ）に `C:\pagefile.sys <min> <max>`、システム管理は `C:\pagefile.sys 0 0`。
- **要管理者**（SeCreatePagefilePrivilege）。**反映に再起動が必須**。
- ⚠️ **MS既知バグ**：AutomaticManagedPagefile=$false にすると複数 pagefile が生成される事例 → 自動管理OFF後は PagingFiles を**1エントリに明示**して塞ぐ。
- リスク：🔴 **本アプリ史上最高**（値を誤るとブート不安定・休止/クラッシュダンプに影響）。

### 2-2. 安全設計（🔴 の肝・"いじくる代替"の責任）

1. **読取専用の状態表示は常に安全**（昇格不要で現状を見せる）。書込だけ Red ダイアログ＋管理者＋退避＋理解チェックでゲート。
2. **推奨＝自動管理（Windowsに任せる）**＝中立の安全既定。`RecommendedValue` 相当はこれ。
3. **"ページングファイル無効化（なし）" プリセットは出さない**（ブート/ダンプ/休止リスク）。手動はサイズ指定のみ。
4. **手動サイズの検証**：初期 ≤ 最大／最大 ≤ 物理RAM×安全上限（例 ×4 or 上限ハードキャップ）／初期 ≥ 下限（例 16MB・実質「ほぼ無効」を弾く）。範囲外は適用拒否＋理由表示。
5. **first-touch 退避**：現状（AutomaticManagedPagefile ＋ PagingFiles 全文）を BackupService に退避 →「元に戻す」で復帰。
6. **復元ポイント誘導**：適用前に「復元ポイントを作成してから進めることを推奨」＋既存 `CreateRestorePointCommand` への導線。
7. **純正へ逃がす**：「Windowsの仮想メモリ設定を開く」＝`SystemPropertiesPerformance.exe`（→ 詳細設定 → 仮想メモリ）。スクショの純正ダイアログそのもの。
8. **再起動の明示**：適用後「変更は再起動後に反映されます」＋「今すぐ再起動／後で」。

## 4. 検証方針（在席時・別途）

- グラフィック：HKCU なので VM 不要・ホストで安全に検証可。アプリ別GPUを設定→`reg query` で値確認→対象アプリ再起動で反映→リセットで原状。
- 仮想メモリ：🔴 **VM 推奨**（Hyper-V WinKnobs-Test）。自動管理ON↔手動↔システム管理の往復＋退避→復元＋再起動反映＋複数pagefile が出ないこと。ホスト実機は再起動を伴うため在席時のみ。
- UIA：`tc_graphics_*` / `tc_virtualmemory_*` 非破壊テスト（状態表示・ボタン活性・ダイアログ開閉）。**入力制御を伴うため、のんさん在席 or 仮想デスクトップで実行**。

## 5. 既知の論点（plan-validator へ投げる観点）

- アプリ別GPU：値名が exe フルパスのため大小文字/区切り/重複の扱い／キー配下に巨大な数の値があった場合の列挙コスト／全体予約名 `DirectXUserGlobalSettings` の確実な除外。
- 全体 Auto HDR：HDR 非対応ディスプレイで ON にしても無効＝誤解を生む文言になっていないか。
- 仮想メモリ：自動管理OFF→複数pagefile バグの確実な封じ／手動サイズの下限・上限の妥当値／読取が昇格なしでどこまで取れるか／適用後の再起動を強制しない設計の安全性／退避の原子性（書込途中で落ちた時）。
- 共通：HKCU 書込の WriteValue が REG_SZ を確実に出すか（kind 明示）／既存 AutomationId 不変／4者択一ペイン切替のリグレッション（Standard/Startup/Network/Graphics）。

## 🔧 plan-validator 反映（2026-06-21・致命3＋重要4＋エッジ5）

### 致命（実装で必ず塞ぐ）
- **致命1（退避タイミング整合）**：first-touch 退避は「退避 JSON が無ければ保存（＝WinKnobs で初めて触る前の状態を1度だけ保護）」。`Load()`（カテゴリ切替のたび呼ばれる）では退避を**上書きしない**。「↩ ぜんぶ元に戻す」の意味論は RDP/HyperV と同じ＝「WinKnobs で初めて変更する前」に戻す（外部変更は対象外と割り切る）。`RestoreAll` 成功後は退避 JSON を削除し、次操作で新規 first-touch を取れる状態にリセット。
- **致命2（Busy 直列化漏れ）**：`MainViewModel._isSystemFeatureBusy` フィールドの `[NotifyCanExecuteChangedFor]` に **VirtualMemory 系コマンド（Open/Restore）を必ず追記**（Source Generator はフィールド定義時に全列挙が必要・後付けはコンパイル通って無効化漏れ）。xUnit で「Busy=true 時に CanExecute=false」を検証。
- **致命3（DeleteValue サイレント失敗）**：`GraphicsService.ResetApp` は **DeleteOrThrow**（削除後に値存在を再確認→残存なら例外）。HKCU なので昇格経路は不要だが「リセットに失敗（他アプリがキー使用中の可能性）」エラーは出す。`RestoreAll` の Delete+Write 組合せも同様にゴースト値残存を確認。

### 重要
- **重要4（exe パス大小文字）**：パス一致判定は全て `StringComparison.OrdinalIgnoreCase`。重複追加は既存行へフォーカス。`SetAppPreference` は既存エントリの**レジストリ格納形式の値名をそのまま使う**（大小違いの二重エントリ防止）。Helper の xUnit に「大小違い同一パスが重複しない」ケース追加。
- **重要5（Auto HDR の HDR 非対応誤案内）**：全体・アプリ別**両方**の Auto HDR に「HDR 非対応ディスプレイでは ON 表示でも無効」注記。可能なら `IsHdrCapableDisplay()` 判定で非対応時グレーアウト＋注記。⚠️ のんさん環境（GTX1080+UHD630・PHILIPS）は HDR 非対応の可能性が高い（memory `user_display_preference`）→ 過度に勧めない中立文言。
- **重要6（再起動前の状態表示乖離）**：`VirtualMemoryState` は「レジストリ値（PagingFiles/AutomaticManagedPagefile・書込済み）」と「CIM 値（稼働中）」の**両方**を取得し、乖離があれば「⏳ 再起動待ちの変更あり」を明示。状態表示を「稼働中の値」と「再起動後に反映される値」で区別。
- **重要7（4者択一の排他）**：`IsStandardCategorySelected + IsStartup + IsNetwork + IsGraphics = 常に 1` を保証。xUnit に「Graphics 選択時に他3つが false」を追加。MainWindow の4ペイン Visibility が同時 Visible にならないことを担保。

### エッジ
- **E1**：`IsAppValueName` で値名の制御文字/NUL/250字超を reject（`ParseTokens` に到達させない）。
- **E2**：`ParseBackup` の `JsonException` を捕捉→破損時は `HasBackup=false` 扱い＋「純正ダイアログで戻して」案内（仮想メモリは特に明示）。
- **E3**：`HasGraphicsBackup` プロパティで「↩ グラフィック設定をぜんぶ元に戻す」ボタンの活性制御（RDP/HyperV の `HasXxxBackup` 踏襲）。退避無し no-op で無反応を防ぐ。
