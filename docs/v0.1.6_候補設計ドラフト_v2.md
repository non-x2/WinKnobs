### A. snapshot 改ざん対策（SHA256 メイン + ACL 任意）

#### A-1. 背景の裏付け数字（脅威モデル）

**現状の攻撃面サイズ**：
- snapshot 保存先：`%APPDATA%\WinKnobs\backup\startup\startup_full_*.reg`
- デフォルトでファイル所有者 = カレントユーザー / Access = フルコントロール（Windows 標準）
- ローテーション：10 件保持（独自）
- ファイルサイズ：典型的に 1-5 KB（9 キー統合 .reg）
- **攻撃面**：10 ファイル × 平均 3 KB = 30 KB の改ざん可能領域

**攻撃シナリオの再現性**：
| シナリオ | 必要権限 | 再現難度 | 影響 |
|---|---|---|---|
| シナリオ 1：PUA がカレントユーザー権限で実行中 | カレントユーザー | 🟡 中 | 🔴 高（HKLM Run への永続化エントリ仕込み）|
| シナリオ 2：他ユーザーアカウントから AppData 上書き | 別ユーザー権限 | 🟢 低 | 🔴 高 |
| シナリオ 3：管理者権限を持つマルウェア | 管理者 | 🔴 高（既に陥落）| 🟡 中（既に侵害済なので差分小）|

**最も対策効果が高いシナリオ**：シナリオ 1（典型的 PUA / 一般的なマルウェア）

#### A-2. スコープ

1. snapshot 生成時：SHA256 ハッシュを別ファイル `startup_full_<timestamp>.sha256` として保存
2. 復元時：ハッシュ照合 → 不一致なら確認ダイアログ（赤色警告）
3. オプション：sha256 ファイル自体に ACL 設定（Owner=管理者・User=Read only）

#### A-3. API シグネチャ案


#### A-5. ACL 設定（オプション・案 A-2）

```csharp
// Services/BackupService.cs に追加（オプション）

private static void TryProtectSnapshotAcl(string filePath)
{
    try
    {
        var fileInfo = new FileInfo(filePath);
        var security = fileInfo.GetAccessControl();

        // 既存ルール全削除（標準ユーザーの書込権限を剥奪）
        security.SetAccessRuleProtection(isProtected: true, preserveInheritance: false);

        var adminSid = new SecurityIdentifier(WellKnownSidType.BuiltinAdministratorsSid, null);
        var userSid = WindowsIdentity.GetCurrent().User!;

        // Admin: フルコントロール
        security.AddAccessRule(new FileSystemAccessRule(adminSid,
            FileSystemRights.FullControl, AccessControlType.Allow));

        // 現在ユーザー: 読込のみ
        security.AddAccessRule(new FileSystemAccessRule(userSid,
            FileSystemRights.Read, AccessControlType.Allow));

        fileInfo.SetAccessControl(security);
    }
    catch (Exception ex)
    {
        // ACL 失敗は致命的でない（SHA256 で 80% 対応済）→ Debug ログのみ
        Debug.WriteLine($"[BackupService] ACL 保護失敗: {ex.Message}");
    }
}
```

### B. 世代またぎ復元の差分件数警告

#### B-1. 背景の裏付け数字

**現状の制約**：
- `ListStartupSnapshots()` で snapshot 一覧取得は可能（10 件まで）
- UI 上は最新 1 件のみ復元可能（`GetLatestStartupSnapshotPath()` 経由）
- ユーザーが「3 つ前の snapshot に戻したい」と思っても UI から不可
- 復元前に「何件のエントリが変わるのか」分からない

**典型的な差分件数の見積**：
- 一般的 Windows 11 環境：Run キー族エントリは合計 10-30 件
- 1 セッション中の変更：1-5 件（個人運用）
- 差分件数のレンジ：0-30 件

#### B-2. スコープ

1. RestoreSnapshot で復元前に差分計算
2. 差分件数（追加 N / 削除 N / 変更 N / 計 M 件）を Confirm ダイアログに表示
3. 差分大（10 件以上）は赤色強調

#### B-3. API シグネチャ案

```csharp
// Services/BackupService.cs に追加

public record StartupDiffResult(
    int AddedCount,
    int RemovedCount,
    int ModifiedCount,
    IReadOnlyList<string> AddedEntries,
    IReadOnlyList<string> RemovedEntries,
    IReadOnlyList<string> ModifiedEntries
)
{
    public int TotalCount => AddedCount + RemovedCount + ModifiedCount;
}

/// <summary>
/// snapshot ファイルと現在のレジストリ状態を比較し差分を算出。
/// snapshot は読込のみ（reg.exe import せず）→ 副作用なし。
/// </summary>
/// <param name="snapshotRegPath">比較対象 snapshot .reg のフルパス</param>
/// <returns>差分結果</returns>
public StartupDiffResult AnalyzeSnapshotDiff(string snapshotRegPath);
```

#### B-4. アルゴリズム

```
1. snapshot .reg を読込 → セクションごと（[HKEY_...]）に分解
2. 各セクションから「key=value」ペアを抽出
   - REG_SZ / REG_EXPAND_SZ は文字列値
   - StartupApproved は Binary（12 byte 最初の 4 byte で enable/disable 判定）
3. 現在のレジストリ（StartupItemsProvider.LoadAll() 相当）を取得
4. キー名 + ハイブで突合：
   - snapshot にあり / 現在ない → Removed（snapshot 復元すると削除されるエントリ）
   ※ 補足：snapshot を「正」として見るので「現在側で増えたもの」が Removed
   - snapshot になし / 現在あり → Added（snapshot 復元すると追加されるエントリ）
   ※ 補足：「現在側で消えたもの」が Added
   - 両方あり・値が異なる → Modified
5. 結果を StartupDiffResult で返却
```

**⚠️ 命名の方向性の注意**：
「snapshot 復元 = snapshot 時点に戻る」が前提：
- snapshot にだけある key = 復元すると「追加」される（Added）
- 現在だけにある key = 復元すると「削除」される（Removed）
- v1 では逆向き表記だったため、v2 で正規化（snapshot 視点を「正」とする）

#### B-5. RestoreSnapshot への組込

挿入位置：`var confirm = _dialogs.Confirm(...)` の前（L530 の前）

```csharp
// B-5 差分件数事前計算（v0.1.6）

var diffSummary = diff.TotalCount switch
{
    0 => "✅ 差分なし（snapshot と現在の状態は一致しています）",
    < 10 => $"  追加 {diff.AddedCount} / 削除 {diff.RemovedCount} / 変更 {diff.ModifiedCount}（計 {diff.TotalCount} 件）",
    _ => $"⚠️ 大規模変更：追加 {diff.AddedCount} / 削除 {diff.RemovedCount} / 変更 {diff.ModifiedCount}（計 {diff.TotalCount} 件）"
};

    $"最新のスタートアップ snapshot から復元しますか？\n\n" +
    $"  ファイル：{Path.GetFileName(latest)}\n" +
    $"  作成日時：{File.GetLastWriteTime(latest):yyyy-MM-dd HH:mm:ss}\n" +
    $"  差分：{diffSummary}\n\n" +
    "※ レジストリの全 6 Run キー + 3 StartupApproved キーが\n" +
    "  snapshot 時点の状態に上書きされます。\n" +
    "※ HKLM 系の上書きは管理者権限が必要です。",
```

```csharp
public partial class RestorePreviewViewModel : ObservableObject
{
    public IReadOnlyList<string> AddedEntries { get; }
    public IReadOnlyList<string> RemovedEntries { get; }
    public IReadOnlyList<string> ModifiedEntries { get; }

    public int AddedCount => AddedEntries.Count;
    public int RemovedCount => RemovedEntries.Count;
    public int ModifiedCount => ModifiedEntries.Count;
    public int TotalCount => AddedCount + RemovedCount + ModifiedCount;

    [ObservableProperty]
    private bool _isConfirmed;  // チェックボックスバインド

    public bool CanRestore => IsConfirmed && TotalCount > 0;
    public bool IsApproved { get; private set; }  // OK 押下後 true

    public RestorePreviewViewModel(StartupDiffResult diff)
    {
        AddedEntries = diff.AddedEntries;
        RemovedEntries = diff.RemovedEntries;
        ModifiedEntries = diff.ModifiedEntries;
    }

    [RelayCommand(CanExecute = nameof(CanRestore))]
    private void Ok() { IsApproved = true; }

    [RelayCommand]
    private void Cancel() { IsApproved = false; }
}
```

| EC-5 | ダイアログをキャンセルした際の Restore 動線 | `if (!approved) return;` の早期 return |
