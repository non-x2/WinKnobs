## 1. 何を・なぜ

- Windows 11 のタスクバー検索の表示形態（表示しない / 検索アイコンのみ / 検索ボックス / 検索ボタン）を WinKnobs から 1 クリックで切替える。
- 既存の **Command 型プリセット**（TaskManager / MessageDuration と同型）。HKCU・管理者不要・低リスク（🟢 Green）。
- 需要 D=8（タスクバーの幅を取る検索ボックスを消したい需要が高い）／note 連動 N=7。

## 2. レジストリ仕様（権威確認済み）

- キー：`HKCU\Software\Microsoft\Windows\CurrentVersion\Search`
- 値名：`SearchboxTaskbarMode`（REG_DWORD）
- 値＝表示モード（**値がそのまま選択肢インデックス**）：
  - `0` 表示しない（非表示）
  - `1` 検索アイコンのみ
  - `2` 検索ボックス（広い）
  - `3` 検索ボタン（新しめのビルド）
- 反映：エクスプローラ再起動で確実（多くは比較的すぐ反映）。WinKnobs はエクスプローラを自動再起動しない（情報提示のみ）＝`RestartScope.Explorer`。
- 出典：pureinfotech / elevenforum / std.rocks（Win11 24H2 で 0-3 を確認）。
- ※ `SearchboxTaskbarModeCache` は「新規ユーザープロファイル既定」用。現ユーザーの切替は `SearchboxTaskbarMode` が主＝**こちらのみ書く**（最小変更・他ツール/設定UIと同じ）。

## 3. 設計（既存 Command プリセット型に完全準拠）

- 純粋関数 `SearchBoxModeHelper`（I/O なし・xUnit 対象）：
  - `Choices`（4・index=レジストリ値）／`ValueForLabel(label)→0..3 or -1`／`LabelForValue(int)→Choices[i]`／`IsValidMode(int)`／`CoerceInt`（共通 `RegistryValueCoercion` 委譲・REG_SZ "2" 混在対応）。
- I/O は `MainViewModel.BuildTaskbarSearchItem`（MessageDuration/TaskManager と同じ I/O だけ担う）：
  - `Read`：現在値 v を読む。`v` が 0..3 → `Choices[v]`。**未設定（null）or 範囲外 → 非適用センチネル「（変更しない・現在のまま）」**（ComboBox 安全・既定モードを誤表示しない＝NightLight の sentinel 流儀）。
  - `Apply`：センチネルなら no-op。実選択なら `ValueForLabel`→DWORD 書込。
  - `Backup`：`{ValueExisted, Value}` を JSON 退避（TaskManager/MessageDuration と同型）。
  - `Restore`：`ValueExisted` なら書戻し、未設定なら `DeleteValue`（＝元が未設定なら削除して既定へ）。
- 危険度 `Green`／`RestartScope.Explorer`／中立表示（特定モードを推奨しない・既定マークなし）。
- カテゴリ：`Desktop`（既存・専用ペイン不要＝標準 DataGrid 表示）。

## 4. テスト（build + xUnit のみ・実機/GUI 不使用）

- `Choices` は 4 件・index と値が一致。
- `ValueForLabel`：各ラベル→0/1/2/3、不正ラベル→ -1。
- `LabelForValue`：0..3→`Choices[i]` の**同一参照**（リテラル直書き禁止＝黙って既定化を防ぐ）。
- `IsValidMode`：0..3 true・-1/4/null 相当 false。
- `CoerceInt`：REG_SZ "2"・0x2 等を 2 に正規化。
- Backup レコードの JSON 往復（ValueExisted/Value 保持）。

## 5. エッジケース

| # | ケース | 対処 |
|---|---|---|
| E-1 | 未設定（新規プロファイル等） | Read はセンチネル表示・Apply で初めて明示書込・Restore で DeleteValue（未設定へ戻す） |
| E-2 | 範囲外/非数値（例 5・REG_BINARY 改変） | **WinKnobs 管理外**として扱う（`TryGetManagedMode`=false）。Read はセンチネル・Backup は ValueExisted=false → Restore は DeleteValue で WinKnobs の書込みを取り消し OS 既定へ戻す（誤って 0=非表示 を書かない・cross-reviewer 重要⑦ 反映）。v0.3.0 グラフィックの「型/範囲外は管理外」方針と整合 |
| E-3 | REG_SZ "2" 混在 | `CoerceInt` で数値化（既存共通ヘルパー） |
| E-4 | 反映タイミング | `RestartScope.Explorer`＋説明に「エクスプローラ再起動で反映」明記（自動再起動はしない） |
| E-5 | Windows「設定」を開いたまま適用 | 説明に「設定アプリは閉じてから」注記（MessageDuration と同様の競合注意） |

## 6. plan-validator への論点

1. 未設定/範囲外時のセンチネル方式（vs 既定ラベルへ丸める）の妥当性。
2. `SearchboxTaskbarModeCache` を書かない判断（現ユーザー切替には不要か）。
3. `RestartScope.Explorer`（自動再起動しない情報提示）で UX 十分か。
4. 値=インデックスの直対応で「nearest preset」が不要な点の確認。

## 🔧 cross-reviewer 反映（2026-06-22・@cross-reviewer Sonnet／本節が本文より優先）

> ⚠️ @plan-validator は一時的に利用不可だったため、設計の自己検証＋本 cross-reviewer（実装後）＋build/xUnit で品質を担保。

- **致命⑥（Restore の DeleteValue サイレント失敗・見落とし事例 2026-06-10 の再現）**：採用・修正済み。
  `RegistryService.DeleteValue` は失敗時 false（例外を投げない）。Restore の未設定復元経路を **delete-or-throw**（false なら `InvalidOperationException`）に変更し、無音の復元失敗を排除。
- **重要⑦（非管理値を Backup→誤って 0 を Restore）**：採用・修正済み。
  `SearchBoxModeHelper.TryGetManagedMode(raw, out mode)` を新設し、**0..3 に coerce できる値だけを「管理対象」**とする。非数値（REG_BINARY 等）・範囲外（5）・未設定は ValueExisted=false → Restore は書込まず DeleteValue（OS 既定へ）。E-2 を上記の通り更新。
- **重要⑧（Backup ロジックのテスト不在）**：採用・対応済み。
  管理対象判定を `TryGetManagedMode` に集約し Read/Backup が共用＝**判定ロジックを xUnit 化**（int 0..3／REG_SZ "2"／null／範囲外／非数値／mode=0）。
- **重要④（同型 Backup private class の重複・Rule of Three 超え）**：本コミット見送り（既存 verified コードのリファクタは回帰リスク・スコープ外）。**フォロー候補**＝`{bool ValueExisted; int Value}` を共通 record へ集約。
- **軽微①②③⑤⑨**：監視のみ。①レジ DWORD は即時書込み＝適用直後の Read が新値を返し IsModified 解消（Explorer 再起動は視覚反映のみ）。⑨ SearchboxTaskbarMode は 0..3 で int 返却＝uint 実害なし。
