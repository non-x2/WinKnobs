# WinKnobs v0.1.7 設計ドラフト：ネットワーク実用機能（初心者向け直感UX）

> 作成：2026-06-01 / ステータス：**ドラフト（plan-validator 未・実装未・push 未）**
> 上位方針：のんさん指示「ネットワーク設定を**徹底的に直感的に・初心者でも簡単に**設定できるのが良い」
> 段階導入：**v0.1.7＝実用3機能（DNS / リセット / 帯域抑制）＋共通「元に戻す」** → v0.2.2＝NIC詳細 / TCP（計画通り）
> 前提診断：のんさんの Claude 遅延の真因は Anthropic 容量＋モデル設定（memory `reference_claude_disconnect_network_diag`）であり、本機能は「AI を速くする」ものではなく「**汎用ネットワーク調整を初心者でも安全に**」が目的。

## 0. 設計原則（このカテゴリの憲法）

> **大方針：初心者ファーストを徹底 → 上級者向けは「その後」。** 初心者の視界には常にボタン数個だけが見える状態を保ち、上級者向けは折りたたみの奥（`▸`）に隠す。本格的な詳細（NIC/TCP）はさらに先の v0.2.2 へ。**段階を飛ばさない**のがこのカテゴリの設計思想。

1. **三層構造（初心者→中級→上級を明確に分離）**：
   - **A 初心者層（常時表示）**：「かんたん設定」ボタン＋**🪟 Windows純正画面を開く**＋「↩ 戻す」だけ。これだけで完結できる。
   - **B 中級層（`▸ くわしい設定` を展開）**：DNS手入力・アダプタ個別指定・DoH ON/OFF。
   - **C 上級層（v0.2.2・本ドラフト範囲外）**：NIC アダプタ詳細・TCP チューニング。
2. **専門用語を画面に出さない**：「DODownloadMode=0」ではなく「通信を軽くする」。
3. **押す前に必ず説明**：「何が変わる？／元に戻せる？」をやさしい日本語で（既存 `DialogService.ConfirmDestructive` 流用）。
4. **今の状態を一目で**：現在の DNS・通信の調子をペイン上部に常時表示。
5. **安全装置を常設**：適用前の値を自動退避し、`↩ ぜんぶ元の状態に戻す` を1クリックで。**「簡単に変えられる」と「すぐ戻せる」は両輪**（初心者がネットを壊して途方に暮れる事故を防ぐ最重要要件）。
6. **戻せない操作は明示隔離**：再起動が要る／元に戻らない操作（リセット）は色・アイコン・既定いいえで隔離。
7. **抱え込まず純正へ逃がす**：WinKnobs で全部やろうとしない。細かい/危ない設定は **Windows 純正画面をワンクリックで開いて** ユーザーに委ねる（壊す責任を WinKnobs が負わない安全弁・初心者の「困ったらここ」の入口）。

## 2. UI 設計（ネットワーク専用ペイン）

Startup カテゴリと同じ「Grid 重ね合わせ＋Visibility 切替」方式で専用 UserControl を出す。

```
┌─ 🌐 ネットワーク ───────────────────────────┐
│  今の状態                                     │
│  DNS：自動 (192.168.1.1)     通信：良好 🟢    │
│  配信最適化(P2P)：オン                        │
│                                              │
│ ━━ かんたん設定（おすすめ）━━                 │
│  [🚀 通信を軽くする ]  余計な自動通信を抑える  │
│  [🌐 DNSを速くする  ]  Cloudflare に変更       │
│  [🔧 不調を直す     ]  ネット設定をリセット    │
│                                              │
│ ━━ Windowsの画面を開く ━━                     │
│  [🪟 ネットの状態] [📶 Wi-Fi] [🔌 アダプター] │
│  [🌍 ネットワークと共有センター]              │
│                                              │
│ ━━ 安心 ━━                                   │
│  [↩ ぜんぶ元の状態に戻す]   （変更前に自動退避）│
│                                              │
│  ▸ くわしい設定を開く（上級者向け）            │
│     └ DNS手入力 / アダプタ個別 / DoH ON-OFF   │
│       （将来：NIC詳細・TCP をここに増設）      │
└──────────────────────────────────────────────┘
```

- 上部「今の状態」：起動時とアダプタ変更時に `Get-DnsClientServerAddress` 等で読み取り表示。
- 「かんたん」ボタンは押下→**説明付き確認ダイアログ**→適用→トースト/ステータス通知。
- 「Windowsの画面を開く」群：純正設定画面をワンクリック起動（開くだけ＝確認不要・最も安全）。
- `▸ くわしい設定` は WPF `Expander`（既定折りたたみ・初心者の視界から隠す）。

## 3. 各機能の技術設計

> ⚠️ 重要：**ネットワーク設定は「レジストリ」と「netsh/PowerShell コマンド」が混在**する。退避/復元方式が項目で異なる（下記）。`CommandAction` の `Backup`/`Restore` に項目ごとに実装する。

### 3-1. DNS プロファイル切替（型：Command / CommandAction）

- **選択肢（Choices）**：`自動 (DHCP)` / `Cloudflare (1.1.1.1)` / `Google (8.8.8.8)` /（詳細層）`手入力`
- **適用 Apply**：
  - 自動：`Set-DnsClientServerAddress -InterfaceIndex <idx> -ResetServerAddresses`
  - 固定：`Set-DnsClientServerAddress -InterfaceIndex <idx> -ServerAddresses ("1.1.1.1","1.0.0.1")`
- **対象アダプタ**：初心者＝**全アクティブ物理アダプタ一括**。仮想（Hyper-V/WSL/VPN/Loopback）は `Get-NetAdapter | Where Virtual -eq $false` 相当で**除外**（誤適用防止）。詳細層でアダプタ個別指定。
- **DoH（DNS over HTTPS）**：Windows 11 標準対応。詳細層トグル。
  - `netsh dns add encryption server=1.1.1.1 dohtemplate=https://cloudflare-dns.com/dns-query autoupgrade=yes`
  - レジストリ補助：`HKLM\SYSTEM\CurrentControlSet\Services\Dnscache\InterfaceSpecificParameters\<GUID>\DohInterfaceSettings\Doh\<ip>`
- **Backup**：適用前に各対象アダプタの `Get-DnsClientServerAddress` 結果（InterfaceIndex→ServerAddresses[]）を **JSON トークン**化して保持。
- **Restore**：トークンから各アダプタへ再適用（空＝DHCP なら `-ResetServerAddresses`）。
- **危険度 🟡**：DNS を変えてもネットは切れにくく、切れても**ローカル操作で戻せる**（戻すボタンはネット不要）。
- **管理者**：要（DNS 変更は要昇格）。未昇格なら `ConfirmElevation`（BUG-3 ルート）。

### 3-2. ネットワーク不調リセット（型：CommandAction・実行ボタン）

- **2 段階に分離**（初心者の恐怖を軽減）：
  - **軽いリセット（再起動不要）**：`ipconfig /flushdns` ＋ `ipconfig /release` → `/renew`（または `Restart-NetAdapter`）。危険度 🟡。
  - **完全リセット（要再起動）**：`netsh winsock reset` ＋ `netsh int ip reset`。危険度 🔴。**カスタム設定が消える＋再起動必須**。
- **戻せない**：`CanRestore=false`（Backup/Restore=null）。→ 必ず **`ConfirmDestructive`（既定いいえ・警告）**＋「この操作は元に戻せません。完了後に再起動が必要です」を明示。
- **完全リセット後**：再起動を促すダイアログ（`PrivilegeService.ShutdownCurrentProcess` は使わず、ユーザー任意再起動）。
- **管理者**：要。

### 3-3. バックグラウンド帯域抑制＝配信最適化 P2P（型：Command / CommandAction）

- **選択肢**：`標準（P2P オン）` / `軽くする（P2P オフ・推奨）`
- **適用**：レジストリ `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\DeliveryOptimization\Config`（または Policies 下）の `DODownloadMode`
  - `0`＝HTTP のみ（P2P 完全オフ）／`1`＝LAN 内のみ／`3`＝インターネット含む（既定）
  - 「軽くする」＝`0` を書込。
- **Backup/Restore**：既存 `BackupService.ExportKey` / `ImportKey`（.reg 退避）を流用。
- **注記（必須表示）**：「他の PC への更新配布が止まります（ご家庭で PC が1台なら影響なし）。Windows Update 自体は止まりません」。
- **危険度 🟡**：レジストリ値・確実に戻せる。
- **管理者**：要（HKLM）。

### 3-0. Windows 純正画面ランチャー（型：単純ボタン・CommandAction 不要）

> 最も安全で実装も最軽量。`Process.Start` で純正画面を開くだけ。**管理者不要・退避不要・確認不要**。初心者の「困ったら純正へ」の入口。

- **実装**：`Process.Start(new ProcessStartInfo(target) { UseShellExecute = true })`
- **ボタンと起動先（target）**：

  | ボタン | target | 開く画面 |
  |---|---|---|
  | 🪟 ネットの状態 | `ms-settings:network-status` | 設定＞ネットワークの状態 |
  | 📶 Wi-Fi | `ms-settings:network-wifi` | 設定＞Wi-Fi |
  | 🔌 アダプター | `ncpa.cpl`（`control.exe ncpa.cpl`） | クラシックなネットワーク接続一覧 |
  | 🌍 共有センター | `control.exe /name Microsoft.NetworkAndSharingCenter` | ネットワークと共有センター |
  | （詳細層）プロキシ | `ms-settings:network-proxy` | 設定＞プロキシ |
  | （詳細層）VPN | `ms-settings:network-vpn` | 設定＞VPN |

- **エッジ**：`ms-settings:` URI が効かない環境（稀）に備え、起動失敗を catch して `control.exe` 系へフォールバック or Info 案内。Win11 26200 は全て対応。
- **危険度 🟢**：何も変更しない（画面を開くだけ）。

### 3-4. 共通「↩ ぜんぶ元の状態に戻す」

- 各機能が「適用」時に生成した Backup トークン（DNS=JSON / 配信最適化=.reg パス）を **ネットワーク用退避ストア**に集約保持。
- 「戻す」押下で、保持中の全トークンを各機能の `Restore` で巻き戻す。
- リセット（3-2）は戻せないので対象外（その旨をボタン説明に明記）。
- 退避ストアの実体：`%APPDATA%\WinKnobs\backup\network\` に最新状態を1セット保持（Startup snapshot と同じ流儀・ローテーション 5〜10）。

## 5. エッジケース（plan-validator 先回り）

1. **複数アクティブアダプタ**（有線＋無線＋VPN＋Hyper-V vEthernet）→ 物理のみに絞る。仮想・Loopback・トンネルを除外。除外ロジックを誤ると VPN/WSL を壊す → **物理判定を厳格に**。
2. **DNS 手入力の検証**（詳細層）→ IPv4/IPv6 形式チェック（`IPAddress.TryParse`）。不正値は適用ブロック。
3. **未昇格での実行**→ `ConfirmElevation`（再起動/続行/キャンセル）。管理者再起動後に同じ操作へ戻れる導線（Startup の HKLM 動線と同様）。
4. **配信最適化がグループポリシー管理下**（企業 PC）→ HKLM 書込が効かない/弾かれる → 書込後に読み戻して**反映失敗を検出**し「ポリシーで管理されています」案内（Info 化）。
5. **DoH 非対応環境**→ Win11 26200 は対応。念のため OS ビルド判定し、非対応なら詳細層トグルを無効化。
6. **完全リセット後の戻し不可**→ `CanRestore=false` を UI に反映（戻すボタンの対象から除外）。
7. **DNS 変更でネット切断**→ 戻す操作はローカル（ネット不要）で完結することを保証。
8. **退避トークンの世代衝突**→ 管理者版/非管理者版で同一退避ファイルを上書きしないようミリ秒命名（v0.1.6 機能 A の知見流用）。

## 6. テスト方針

- **xUnit（純粋関数）**：
  - DNS 候補→`Set-DnsClientServerAddress` 引数生成のラウンドトリップ
  - DNS 退避 JSON トークンの直列化/復元（InterfaceIndex→Addresses）
  - `DODownloadMode` 値マップ（標準=3 / 軽い=0）
  - IPv4/IPv6 入力検証（正常・異常・境界）
  - アダプタ物理判定（仮想/VPN/Loopback 除外）のテーブル駆動
- **UIA（VM 必須）**：ネットワークペイン表示・3 ボタン＋戻す存在・Expander 展開・確認ダイアログ検出（MessageBox は v0.1.6 同様 UIA 制約あり＝目視併用）。
- **VM 実機検証必須**：実際の DNS 変更・リセット・配信最適化は**ホストのネットを壊さないため必ず VM で**。`Before_v0.1.7_Network` チェックポイントを取得してから。

## 8. リスクと「やらない」判断材料

- 🔴 **最大リスク＝初心者がネットを壊す**：完全リセットと DNS 誤設定。→ 設計原則 5/6（戻す常設・戻せない操作の隔離）で封じる。
- ⚠️ **「AI が速くなる」誤期待**：UI に「通信を快適にする一般設定です」と明記し、過大広告にしない。
- 🟢 **やらない選択肢**：もし「初心者が壊すリスク」をのんさんが重く見るなら、v0.1.7 は **DNS と配信最適化（戻せる2つ）だけ**にして、リセット（戻せない）は v0.2.x へ後ろ倒しも可。

## 9. v0.2.2 への拡張受け皿

`▸ くわしい設定` の Expander 内に、将来そのまま増設：
- NIC アダプタ詳細：`Get-NetAdapterAdvancedProperty` / `Set-NetAdapterAdvancedProperty`（RSS・割込加減・省電力 EEE・Jumbo）

- これにより v0.1.7 の UI 骨格が v0.2.2 をそのまま飲み込める。
