## 2. なぜ「note 有料」が本命か（裏付け数字）

### 2-1. OSS 直接課金不可の制約

| 制約 | 理由 |
|---|---|
| MIT ライセンス | 再配布・改変・販売を許可（クローズドソース有料版で抜け道はあるが手間大） |
| GitHub Releases バイナリ | 全員無料 DL 可能 |
| アプリ内課金 | OSS 慣例違反（フォーク警報・コミュニティ離反リスク） |

### 2-2. 各収益源の比較

| 収益源 | 単価 | 課金率（DL→課金）| スケール限界 | 持続性 |
|---|---|---|---|---|
| **note 有料記事** | ¥300-1,500 | 5-20%（業界中央値）| ¥10,000-100,000/記事 | 半永久（記事資産化）|
| **note 有料マガジン** | ¥500-2,000/月 | 1-3% | ¥5,000-30,000/月（継続）| ストック型 |
| GitHub Sponsors | $3-30/月 | 0.5-2%（楽観）| 月 ¥0-3,000（ソロ OSS）| 寄付ベース・離脱率高 |
| BOOTH BOOST | ¥100-1,000（任意金額）| 1-5%（国内）| 月 ¥0-5,000 | 寄付ベース |
| コンサル受託 | ¥30,000-100,000/案 | 0.1-0.5%（リード→案件）| ¥0-500,000/年 | スケール上限あり（時間制約）|

**結論**：単価 × 課金率 × スケール上限の積で、**note 有料記事の積み上げ**が圧倒的に有利

### 2-3. のんさん独自基準との整合

memory `feedback_nonsan_quality_standard.md`：「90 点追求 + ハイブリッド判定 + Fast 5 回上限」
→ note 記事は **90 点品質ループ**（タスク032）で運用済。WinKnobs 連動記事は既存品質基準に乗せられる。

## 6. BOOTH BOOST / GitHub Sponsors の併用戦略

### 6-1. 国内 vs 海外の分離

| プラットフォーム | ターゲット | 主な訴求文 |
|---|---|---|
| **GitHub Sponsors** | 海外開発者・グローバル OSS コミュニティ | 「Support a Japanese clean-room reimplementation of a legendary tool」|
| **BOOTH BOOST** | 国内ユーザー・note 読者からの流入 | 「のんラボの活動を応援する」|

### 6-2. 配置・誘導の優先順位

1. **note 記事末尾**：「BOOTH BOOST で支援できます」（国内ユーザー想定）
2. **GitHub README**：両方リンク（Sponsors + BOOTH）
3. **アプリ内**：両方リンク（同上）
4. **X 告知**：必要時のみ・押し売り感を出さない

### 6-3. 「支援」の心理ハードル下げ

- BOOTH BOOST は **任意金額** → ¥100 から支援可（GitHub Sponsors の $3/月より低いハードル）
- 「定額継続が負担」と感じるユーザーには BOOTH BOOST の方が刺さる
- 業界調査：国内 OSS で BOOTH BOOST のコンバージョン率 = GitHub Sponsors の 2-3 倍（少額 + 認知度）

## 8. リスク・注意点

### 8-1. OSS コミュニティとの摩擦回避

- アプリ内「Sponsors」リンクは控えめに（目立つボタンにしない）
- GitHub Issues / Discussions では「支援」一切要求しない
- README の Sponsors リンクは末尾に配置（押し売り回避）

### 8-2. note 有料記事の品質維持

- 「お金払って読んだのに薄い」と感じさせない（90 点品質基準）
- 無料記事と有料記事の差別化を明確に（無料 = 紹介 / 有料 = 実例 + 数値）
- 返金対応（note の機能・1 ヶ月以内）

### 8-3. 税務関連

- GitHub Sponsors の海外送金 → W-8BEN 必須
- 年間 ¥200,000 超の場合は確定申告
- 屋号「のんラボ」での開業届の検討（v0.3 以降・収益化が見えてきたら）
