## 0. 目的・スコープ

Windows の「テキストのサイズ」（設定 > アクセシビリティ > テキストのサイズ）を WinKnobs から
1クリックで切替える。レジストリ `HKCU\Software\Microsoft\Accessibility\TextScaleFactor`(REG_DWORD) を書く。

- **管理者不要**（HKCU）
- **危険度 🟢**（すぐ戻せる・既存 Backup/Restore 機構に載せる）
- **ディスプレイ拡大率(DPI)とは別物**。これは「文字だけ」を拡大する Win11 アクセシビリティ機能。

### スコープ外（v0.2 候補）
- 連続スライダー UI（本実装はプリセット選択式）
- 他の a11y つまみ（ハイコントラスト・カーソルサイズ・マウスポインタ等）→ 新カテゴリの将来拡張余地

## 1. 実装方針：TaskbarSi と同じ `Command` 型（プリセット選択式）

理由（他案との比較）：

| 案 | UI | 無効値ガード | 新規コード | 判定 |
|---|---|---|---|---|
| ⭐ Command型/プリセット | 既存 ComboBox | プリセットのみ＝不正値不可 | helper+Build のみ | **採用** |
| DWord型/数値直接入力 | 既存 TextBox | **範囲検証なし**（DWord適用パスは下限0のみ・上限なし） | 範囲検証の追加改修が必要 | 却下（既存パス改修リスク） |
| スライダー新設 | 新XAMLコントロール | あり | 新UI+バインド+plan/cross追加面 | 却下（スコープ膨張） |

→ `BuildTaskbarSizeItem()`（MainViewModel.cs:1354）と同型で `BuildTextScaleItem()` を作る。
inline Backup/Restore 付き。`SettingDialogViewModel` の Command 型適用パスにそのまま載る（コード改修不要）。

### プリセット
`100%（既定）/ 125% / 135% / 150% / 175% / 200% / 225%`
- 値＝パーセント実値（TaskbarSi のような index ではない点に注意）。
- `135%` を入れる理由：のんさんが 4K で愛用（dogfooding）。ただし **UI 上「推奨」マークは付けない**（後述 §4）。

## 3. API 設計

### Services/TextScaleHelper.cs（新規・static・I/O 無し＝xUnit 対象）
```csharp
public static class TextScaleHelper
{
    public const string RegistryPath = @"HKCU\Software\Microsoft\Accessibility";
    public const string ValueName    = "TextScaleFactor";
    public const int    MinScale = 100;
    public const int    MaxScale = 225;
    public const int    DefaultScale = 100;   // Windows 既定（未設定時もこれ）

    // パーセント実値のプリセット
    public static IReadOnlyList<int> PresetValues { get; } = new[] { 100,125,135,150,175,200,225 };
    // ComboBox 表示ラベル（PresetValues と同順・同数）
    public static IReadOnlyList<string> Choices { get; } = new[]
        { "100%（既定）","125%","135%","150%","175%","200%","225%" };

    public static int  ClampToRange(int value);                 // [100,225] に丸め
    public static string ToLabel(int value);                    // 100→"100%（既定）" / 135→"135%" / 範囲外はClamp後
    public static bool TryParseLabel(string label, out int value); // "135%"→135 / "100%（既定）"→100 / 不正→false
    public static string NearestPresetLabel(int value);         // 任意値→最も近いプリセットのラベル（Read 用・ComboBox整合）
}

public sealed record TextScaleBackup
{
    public bool ValueExisted { get; init; }
    public int  Value { get; init; }
}
```

### MainViewModel.BuildTextScaleItem()
```
Id="accessibility.textScaleFactor", Category=Accessibility, Risk=Green,
RestartScope=Logoff（完全反映は再ログイン）, ValueType=Command,
RecommendedValue="100%（既定）", DefaultValue="100%（既定）",
Command:
  Read    = () => 値読込（object→int）。値なし→"100%（既定）" / 値あり→NearestPresetLabel(value)
  Apply   = label => TryParseLabel→Clamp→WriteValue<int>(path,name,value,DWord)
  Backup  = () => 現在値を読み TextScaleBackup{ValueExisted, Value(=生値)} を JSON 化（TaskbarSiBackup と同流儀）
  Restore = token => ValueExisted? WriteValue(生値) : DeleteValue
```
- **Read と Backup を分離**：Read は ComboBox 整合のため最近接プリセット、Backup は復元忠実性のため**生値**を保存。

## 4. 重要な設計判断（レビュー観点・先回り）

### 判断1：WM_SETTINGCHANGE ブロードキャストは「見送り」
- のんさん発案メモには「書込後に WM_SETTINGCHANGE 全体ブロードキャスト」とあるが——
- TextScaleFactor は実際には**サインアウト→再ログインで反映**（システムのテキストスケール再適用は WM_SETTINGCHANGE では確実に走らない）。
- 既存コードに P/Invoke ブロードキャスト基盤は**無い**（grep 0件）。効果の無い死にコード＋ネイティブ面の追加はリグレッション面を増やすだけ。
- 既存 TaskbarSi も「エクスプローラ再起動で反映」と**案内のみ**＝同じ流儀。
- → Description に「完全反映はサインアウト→再ログイン」と明記。broadcast は実装しない。

### 判断2：「推奨135%」は出さない（中立表示）
- memory `feedback_no_text_scaling`＝「拡大率を私から推さない」。
- OSS 公開ツールで一般ユーザーに 135% を推すのは不適切（アクセシビリティ＝個人最適・既定100%が中立）。
- → `RecommendedValue="100%（既定）"`。Description は中立・a11y 説明のみ。**のんさん個人名/愛用への言及はUIに入れない**（公開ツールのため）。135% は選択肢に入れるだけ。

### 判断3：新カテゴリ新設（既存 Desktop 流用ではなく）
- のんさん発案どおり ♿アクセシビリティ を新設。Windows の設定アプリ構成（アクセシビリティ）と一致＝発見性◎。
- 将来 a11y つまみ（ハイコントラスト等）の受け皿。
- リスク＝UIA `tc_visual_ui.ps1` のカテゴリ数ハードコードのみ（§2 で更新済み）。switch 網羅性破綻は無し（Explore 確認）。
