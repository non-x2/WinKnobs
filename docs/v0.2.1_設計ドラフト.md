## 🔧 @plan-validator 反映（本文より優先・2026-06-11）

1. 🔴 **致命1：powercfg は `scheme_current` 文字列を使わず実 GUID 固定**。Apply 冒頭で `powercfg /getactivescheme` から GUID を1回解決し、Read/Write/Backup を**同一 GUID**で実行（TOCTOU 回避）。GUID 解決失敗時は **Apply 中止**（本文の「パース失敗でも Apply 可」を上書き）。Windows 11 の電源モード overlay で反映されない場合がある旨を Description に明記＋VM で実測。
2. 🔴 **致命2：bcdedit OFF が「効かないのに成功扱い」になる経路を塞ぐ**：
   - **コア分離（VBS）が ON のままだと hypervisorlaunchtype off でも効果なし** → Hyper-V OFF ダイアログに「先にコア分離を OFF にしてください」の依存ガイド（項目5→6 の順序依存を UI 明示）。
   - **BitLocker 有効検知**→「再起動後に回復キーを求められる場合があります」を Red ダイアログに必ず表示。
   - 成功表示は「bcdedit 値を変更しました（効果は再起動後・VBS 残存時は無効）」と言い切らない文言。Secured-core/UEFI ロックの「書いても戻る」注記を項目6にも適用（項目5と対称に）。
3. 🔴 **エッジ3：再起動系の並行 Apply 対策**：メンテ系（コア分離/Hyper-V/WSL）は**1本の共通 Busy で直列化**（DISM グローバル mutex 衝突防止）＋複数適用時は「保留中の変更」を意識した「まとめて再起動でOK」の案内文言。
4. ⚠️ **重要3：SPI_SETMOUSE の配列並びはレジストリ3キーと不一致**。`int[3] = { MouseThreshold1, MouseThreshold2, MouseSpeed(加速ON/OFF) }`（キー名の順と違う）。マッピングは純粋関数化して xUnit 検証。P/Invoke は `SystemParametersInfo(uint, uint, [In] int[], uint)`。
5. ⚠️ **重要4：DeleteOrThrow の適用先を限定**。今回は「値上書き復元」が基本（マウス=1,6,10 書戻し／Throttling=0xa 書戻し）。**値削除が出るのはコア分離の first-touch が「値なし」だった場合のみ**＝そこだけ DeleteOrThrow。方式マップに復元方式列を追加（§1 参照）。
6. ⚠️ **WSL ON の2機能同時 Enable は done-stack 化**（VirtualMachinePlatform 成功・WSL 失敗の中途半端状態に Outcome `PartiallyEnabled` 追加 or 逆順ロールバック）。
7. ⚠️ **Boost 5択→3択に縮小**（0=無効/1=有効/2=アグレッシブ既定）。index 4/5 はハイブリッド CPU 専用で非対応環境（のんさんの Z370 含む）では無視される＝「効かない選択肢」を出さない。
8. ⚠️ **夜間モード blob「キー/Data 値なし」分岐**（夜間モード未使用 PC）：「夜間モードを一度 ON にしてから調整してください」案内（NRE 防止）。
9. ⚠️ **再起動系の「元に戻す」活性タイミング**：適用直後（再起動前）から復元可能になる UX は許容するが、復元側の文言に「再起動前なら適用前の状態に書き戻すだけで安全」と明記（混乱防止）。
10. ⚠️ **ElevationClassifier は PowerShell 前提**：bcdedit/powercfg の exe 直叩きは exit code の出方が違う → exe 系は「非0＋stderr キーワード」で別 Classify（`ExeClassifier` 仮）か、PowerShell 経由に統一（`& bcdedit ...; exit $LASTEXITCODE`）。**PowerShell 経由統一を採用**（既存 Classify 資産を活かす）。
11. ⚠️ **Step7 に「.ps1 BOM hook 不発前提の自前 BOM 確認」を明記**（事例ログ 2026-06-10・本セッションでも2連続不発）。
12. ⚠️ **VM 検証順序制約**：コア分離 OFF にした VM では Hyper-V/WSL 検証の前提が崩れる → 検証順は WSL→Hyper-V→コア分離（依存が深い順に後ろ）＋各検証前に CP。

## 0. 実装前のダメ出し（先に言う問題点）

1. 🔴 **`system.hyperVPlatform` 無効化は、のんさん自身の PC で実行すると WinKnobs の VM テスト基盤（Hyper-V `WinKnobs-Test`）と MemPalace 等が巻き添えで止まる**。エンドユーザー（LDPlayer 勢）向け機能だが、開発機での誤爆が最悪。→ 🔴Red＋RDP有効化と同型の専用強確認ダイアログ必須。
2. 🔴 **Hyper-V 無効化の連鎖影響が広い**：WSL2・Windows サンドボックス・コア分離（メモリ整合性）・Credential Guard・WSA がすべてハイパーバイザ依存。OFF にすると全部止まる。ダイアログに列挙必須。
3. ⚠️ **コア分離 OFF はセキュリティ後退**（HVCI はドライバ悪用攻撃の防壁・無効化でFPS 0〜10%改善の代償）。中立説明＋強確認。再有効化は Windows セキュリティ UI から再起動要の場合あり。
4. ⚠️ **powercfg の出力はロケール依存**（日本語環境で英語キーワード grep 不可）。Boost モードの Read は「GUID 行アンカー＋16進 index の正規表現」で言語非依存パースにする（純粋関数＋xUnit）。
5. ⚠️ **マウス加速はレジストリ書込だけでは即時反映しない**（再ログオンまで旧値）。`SystemParametersInfo(SPI_SETMOUSE)` P/Invoke で即時反映＋レジストリ永続化の2段が必要。
6. **「触らない」検討**：`network.throttlingIndex`（0xffffffff）は配信/音楽制作併用時に逆効果の報告あり → 既定(10)/無効(0xffffffff) の2択＋中立説明で「戻せる」を担保（一律推奨しない）。

## 2. 各項目設計

### 2-1. 夜間モード色温度（v0.2.0 ドラフト §3 を正とする）
[v0.2.0_QuickWin_設計ドラフト.md](v0.2.0_QuickWin_設計ドラフト.md) §3 のまま採用：
- `NightLightHelper.TryParseSettings / BuildPatchedSettings`（1バイトでも想定外なら書込拒否・色温度フィールドのみ差替・タイムスタンプ既存値+1）
- Backup＝blob 丸ごと Base64（解釈不要＝復元は常に安全）・1200〜6500K クランプ・ON/OFF は触らない
- **実装順は最後**（最難関・縮退逃げ道＝「読取表示のみ＋ms-settings:nightlight ジャンプ」を維持）

### 2-2. マウス加速 OFF（`gaming.mouseAcceleration`）
- `HKCU\Control Panel\Mouse` の **3値セット**：`MouseSpeed`/`MouseThreshold1`/`MouseThreshold2`（REG_SZ）。OFF=`0,0,0`／既定=`1,6,10`。
- Command 2択「既定（加速あり）／OFF（ゲーマー向け・1:1）」。Backup＝3値を1つの JSON に（`MouseAccelBackup { Speed, T1, T2 }`）。
- **即時反映**：`SystemParametersInfo(SPI_SETMOUSE, 0, int[3], SPIF_UPDATEINIFILE|SPIF_SENDCHANGE)` P/Invoke（新規 `Native/MouseParams.cs`）。失敗時はレジストリのみ書込＋「再ログオンで反映」案内（フェイルソフト）。
- Risk 🟢／昇格不要／既存 Boolean でなく Command な理由＝3値連動＋型が REG_SZ。

### 2-3. Network Throttling Index（`network.throttlingIndex`）
- `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Multimedia\SystemProfile` の `NetworkThrottlingIndex`（DWORD）。
- Command 2択「既定（10・マルチメディア保護）／無効（0xffffffff・スループット優先）」。
- 既定側は **「値削除」でなく 0xa を書く**（OS 既定はキーに値が存在するため・Power Throttling と逆）。Backup＝StringBackup 値単位。
- Read は ReadValue<string> で 10進文字列比較（DWORD 0xffffffff → "4294967295"）。
- 説明に「配信・DAW 併用時は既定のままが安定する場合あり」を明記（中立）。

### 2-4. プロセッサー Boost モード（`system.processorBoost`）
- 新規 `PowerCfgHelper`（純粋関数）＋ `PowerCfgService`（子プロセス・Sysmain 同型）。
- 書込：`powercfg /setacvalueindex scheme_current sub_processor PERFBOOSTMODE <n>; powercfg /setdcvalueindex ... <n>; powercfg /setactive scheme_current`（1コマンド連結・-ErrorAction 不要の exe）。
- 5択：0=無効／1=有効／2=アグレッシブ（既定）／4=効率的有効／5=効率的アグレッシブ。
- 読取：`powercfg /q scheme_current sub_processor PERFBOOSTMODE` を **GUID アンカー＋`0x[0-9a-f]+` 正規表現**でロケール非依存パース（`TryParseBoostIndex(acOutput)`・AC 値を表示）。パース失敗→「読取不可」表示＋Apply は可（書込は index 指定で安全）。
- Backup＝適用前の AC/DC index を JSON 退避。Risk 🟡・要管理者（HKLM 電源スキーム書込）。

### 2-5. コア分離 OFF/ON（`system.coreIsolation`）🔴
- `HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity` の `Enabled`（DWORD 0/1）。
- ツールメニュー2項目（`MenuEnableCoreIsolation`/`MenuDisableCoreIsolation`）＋ **OFF 側は ConfirmDestructive 強確認**（「ドライバ悪用攻撃への防壁を外します。ゲーム互換/性能目的の一時 OFF を想定。再起動必要」）。
- `WasEnabledBy` 等の同居値は触らない（値単位）。GPO/MDM 管理下（`HKLM\SOFTWARE\Policies\Microsoft\Windows\DeviceGuard` 存在）はグレーアウト＝RDP の IsPolicyManaged 同型。
- Risk 🔴（セキュリティ後退方向）／再起動反映／UEFI ロック環境（Secured-core）では書いても戻る場合あり→事後検証せず「再起動後に Windows セキュリティで確認」案内。

### 2-6. Hyper-V Platform OFF/ON（`system.hyperVPlatform`）🔴最重要
- **方式＝bcdedit 一本**：`bcdedit /set hypervisorlaunchtype off`（OFF）／`auto`（ON）。
  - DISM 機能削除は**不採用**（VM 構成・vSwitch まで消えるリスク＋戻しが重い。bcdedit は機能を残したまま起動だけ止める＝完全可逆・再起動2回不要）。
- 新規 `HyperVHelper`（純粋関数：`BuildSetLaunchTypeCommand(on)`／`TryParseLaunchType(bcdedit /enum {current} 出力)`＝`hypervisorlaunchtype` 行アンカーでロケール非依存）＋ `HyperVService`（子プロセス同型）。
- **専用 Red ダイアログ**（RemoteDesktopEnableDialog 同型・チェックボックス同意・既定キャンセル）：
  - OFF 側の警告列挙：「WSL2／Windows サンドボックス／コア分離（メモリ整合性）／Credential Guard／Hyper-V 仮想マシンが**すべて停止**します。LDPlayer 等のエミュレータを使うための設定です。再起動必要」
  - AutomationId：`HyperVDisableDialog`/`CheckUnderstandHyperVRisk`/`BtnHyperVOff`/`BtnCancel`
- Backup＝適用前の launchtype を JSON 退避（first-touch・maintenance ストア再利用）＋「元に戻す」メニュー。
- Read：launchtype（Auto/Off）をメニュー常設ラベル表示（v0.1.20 世代カウンタパターン流用）。
- Risk 🔴／要管理者／再起動反映。

### 2-7. WSL ON/OFF（`system.wslEnabled`）
- ツールメニュー2項目。実行＝PowerShell 子プロセス：
  - ON：`Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux,VirtualMachinePlatform -All -NoRestart`
  - OFF：`Disable-WindowsOptionalFeature -Online -FeatureName Microsoft-Windows-Subsystem-Linux -NoRestart`（**VirtualMachinePlatform は残す**＝WSA/他機能の巻き添え防止）
- OFF 確認文言：「Linux ディストリビューションのデータ（ext4.vhdx）は削除されません。再有効化で戻ります。再起動必要」
- タイムアウトは DISM 系が遅いため **300秒**（Sysmain の60秒から個別延長）。
- Risk 🟡／要管理者／再起動反映。`wsl --install` は不採用（ディストロDLまで走る＝過剰）。
