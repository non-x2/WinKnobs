## A. タスクバー ボタンの結合（v0.3.15・`desktop.taskbarGlomLevel`）

- **レジストリ**：`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced`
  - `TaskbarGlomLevel`（REG_DWORD）：主タスクバー。
  - `MMTaskbarGlomLevel`（REG_DWORD）：他モニタのタスクバー（24H2 で分割・[出典](https://www.elevenforum.com/t/always-or-never-combine-taskbar-buttons-and-hide-labels-in-windows-11.15135/)）。
  - 値＝選択肢 index（**0/1/2 が index と一致**＝LaunchTo のような値≠index 変換は不要）：
    - `0` = 常に結合（ラベル非表示）／`1` = タスクバーに入りきらないとき／`2` = 結合しない（ラベル表示）。
  - **未設定時の OS 既定は 0（常に結合）** ＝ 値が無い環境は「常に結合」を表示（センチネルにしない＝実挙動と一致・TaskbarSize と同方針）。
- **型**：Command 3 択。**Apply は TaskbarGlomLevel と MMTaskbarGlomLevel の両方に同じ値を書く**（主・他モニタを揃える＝GUI で別々に持てるが、ユーザー期待は「全タスクバー同じ」が大多数）。
- **Read**：`TaskbarGlomLevel` を読み、0/1/2 なら該当ラベル、それ以外/未設定は choices[0]（常に結合）。
- **Backup/Restore**：両値の existed＋値を JSON 退避。Restore は existed=true なら書き戻し、false なら DeleteValue（TaskbarSize と同型・両値それぞれ判定）。
- **RestartScope**：Explorer（エクスプローラ再起動で反映）。
- **Helper**：`TaskbarGlomHelper`（純粋関数・Choices/IndexForValue/ValueForIndex/ValueForLabel/CoerceInt/TryGetManagedIndex）＋ `TaskbarGlomHelperTests`。LaunchToHelper を 0/1/2＝identity 版に簡約。
- **危険度**：🟢（見た目のみ・即戻せる）。

## B. マウスホイールのスクロール行数（v0.3.16・`keyboardMouse.wheelScrollLines`）

- **レジストリ**：`HKCU\Control Panel\Desktop\WheelScrollLines`（**REG_SZ**・数値文字列）。既定 `"3"`。
  - 範囲：1〜100 行（`-1`＝1 画面ずつ は本項目では非対象＝数値モデルを崩さないため。Description に明記）。
- **型**：String 数値（`MenuShowDelay` を厳密踏襲）。`NumericStringRange = (1, 100)`・`RecommendedValue="3"`・`DefaultValue="3"`。
- **カテゴリ**：キーボード・マウス。
- **RestartScope**：**Logoff**（`Control Panel\Desktop` のシステムメトリックは WM_SETTINGCHANGE をブロードキャストしない限り再ログオンで反映＝honest）。
- 新規 Helper 不要（既存 String 数値経路がそのまま処理）。
- **危険度**：🟢。

## C. スタートに「最近追加したアプリ」を表示（v0.3.17・`desktop.startTrackProgs`）

- **レジストリ**：`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced\Start_TrackProgs`（REG_DWORD・`1`=表示/`0`=非表示）。
  - 設定 > 個人用設定 > スタート > 「最近追加したアプリを表示」と同じ。値 1=表示 がユーザー視点 ON と一致＝**InvertDisplay 不要**。
- **型**：宣言的 Boolean（`AutoCheckSelect` を厳密踏襲）。`RecommendedValue=false`（中立＝既定）・`DefaultValue=false`（※ OS 既定は表示=true 寄りだが、ここは「WinKnobs 推奨＝中立」。要 plan-validator 確認＝下記 Q1）。
- **カテゴリ**：デスクトップ・UI。
- **RestartScope**：None（スタートを開き直すと反映・Description に明記）。
- **危険度**：🟢。

## 確認したい論点（plan-validator 向け）

- **Q1（C の DefaultValue）**：Windows の実既定は「最近追加したアプリを表示＝ON（値 1 または未設定で表示）」。`DefaultValue=false` は他の宣言的 Boolean（中立=既定 OFF 表記）に倣ったが、実既定と乖離。`DefaultValue=true`（実既定に合わせる）か `false`（中立）か。
- **Q2（A の MM 両書き）**：MMTaskbarGlomLevel も同値で書くのは過剰介入か。Restore で MM だけ existed=false の場合の削除挙動の正当性。
- **Q3（B の範囲）**：`-1`（1 画面ずつ）を切り捨てる判断の是非。現在値が `-1` や `4` 等のユーザー設定だった場合、String 数値 UI はどう表示・保存するか（範囲外の既存値の扱い）。
- **Q4（A の Read 既定）**：未設定を choices[0]（常に結合）と表示する判断の是非（センチネルにしない）。

## 🔁 plan-validator 反映（2026-06-30）

- **C 全面見直し（最重要）**：
  - キー意味の訂正＝`Start_TrackProgs` は「最近追加したアプリ」ではなく**「よく使うアプリを表示／アプリ起動の記録」**（既定=未設定 or 1＝ON。[出典](https://www.elevenforum.com/t/enable-or-disable-app-launch-tracking-in-windows-11.3727/)）。Title/Description をこの意味に修正。
  - 復元の正しさ＝汎用 Boolean の Backup/Restore は `reg export`→`reg import`（マージ）で、**未設定だった値を import で消せない**。既定 ON の本項目は「OFF にして戻す」で未設定へ戻らない。→ **Command 型2択へ変更**し、`ValueExisted`＋実値を JSON 退避、Restore は existed=false で **DeleteOrThrow**（LaunchTo パターン）。
  - カテゴリ＝Privacy（起動記録＝プライバシー寄り。既存「アクティビティ履歴を無効化」と並ぶ）。
  - 選択肢＝「記録する（既定）」/「記録しない」。Read：1→記録する／0→記録しない／未設定→記録する（既定 ON）。
- **A 補強**：Backup は `TaskbarGlomLevelExisted/Value` ＋ `MMTaskbarGlomLevelExisted/Value` の4フィールド JSON。Restore は各キー existed=true→書戻し／false→**DeleteOrThrow**。Description に「WinKnobs は自動でエクスプローラを再起動しません」「両タスクバー（主・他モニタ）を同じ値に揃えます」を明記。Read は `TaskbarGlomLevel` のみ参照（未設定→常に結合）。Helper テストに identity（0/1/2→同値・3→-1）／TryGetManagedIndex(null)／Read fallback の非自明ケースを必ず入れる。
- **B 補強**：RestartScope は **Logoff 据置**。根拠＝`WheelScrollLines` は各アプリが起動時にキャッシュするシステムメトリックで、`WM_SETTINGCHANGE`/`SPI_SETWHEELSCROLLLINES` のブロードキャストをしない本実装では再ログオンで確実反映（同キーの MenuShowDelay が Explorer なのはシェルが読むため＝別挙動）。SPI 即時反映サービスの新設は本バッチ非対象（scope 維持）。既存値が範囲外（"0"=スクロール無効／"-1"=1画面ずつ／"4" 等）の場合：現在値はそのまま表示し、保存時に範囲(1-100)検証で弾く（汎用 String フロー＝MenuShowDelay と同じ）旨を Description に注記。
- **共通**：Restore の `DeleteValue` は `if(!_registry.DeleteValue(...)) throw new InvalidOperationException(...)`（DeleteOrThrow・見落とし事例ログ 2026-06-10 サイレント失敗対策）。
- **CategoryType 追加不要**（Privacy/Desktop/KeyboardMouse すべて既存・検証済）。テスト .csproj は SDK 既定 glob で新規ファイル自動取り込み（既存テスト追加実績どおり）。
